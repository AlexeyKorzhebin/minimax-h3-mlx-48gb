## 3. Голова продолжения (fl2va от PNG)

Вход: последний кадр s1 (896x512, из mp4). Прогоны fl2va 2 шага при length 22, 73, 124 и сам s2 из п. 1 (192). Кадр 0 сохранён без потерь с декодированного тензора (до h264) и из mp4.
- Число кадров на выходе: 22, 73, 124, 192, ровно `length`.
- Кадр 0 не совпадает побайтно с входом ни в одном случае (max abs 65-77, средний 3,8-4,5 из 255): SSIM кадра 0 с входом 0,919-0,926 (тензор), 0,911-0,916 (mp4); у s2 из п. 1 (50 шагов): 0,926 и 0,916.
- Кадр 1 дальше от входа: SSIM 0,907 (тензор, len 73), 0,899 (mp4 s2); кадр 2: 0,861. Соседние кадры в голове s2 между собой 0,96-0,98. Значит кадр 0 это пересжатая копия входа (дрейф от VAE), дальше идёт движение.
- **Решение по исходу:** `head_drop_frames = 1` для ComfyUI fl2va с `from_frame` (кадр 0 повторяет конец предыдущего ролика), как у sglang. Побайтной идентичности нет, на склейке стык виден по яркости на уровне 4/255, не по смыслу.

## 5. Рестарт ComfyUI (kill -9)

После подъёма (8-10 с): `/queue` пуст, `/history` пуст (`{}`), `lock` у нового процесса.
- (а) во время денойза (шаг 3 из 20): клиент получил разрыв WS; после рестарта в `/history` и `/queue` ничего, файлов `studio/c5a-mid/` нет (SaveVideo пишет в конце).
- (б) сразу после ответа на `POST /prompt`: то же, ничего в `/queue`, `/history`, файлов нет.
- (в) завершённая Krea-задача, затем kill -9: до kill была в `/history`; после рестарта `/history` пуст, но файл `studio/c5c-done/f_00001_.png` остался.
- Время старта процесса меняется (`ps lstart`: 18:23:10 -> 18:46:04 и т. д.), VRAM после kill 307 МБ. Поле `started_at` диспетчера не проверялось: EngineSpec `comfy-studio` в диспетчере не заведён (по заданию его не правим).
- **Решение по исходу:** `find` по `/queue`/`/history` после рестарта ничего не находит, значит работают только ветка по файлам `studio/<task_id>/` (готовые) и `restarted_since`: пустые очередь и история вместе с отсутствием файлов доказывают гибель задачи, один автоповтор допустим, как в §8.5. Оговорка: `restarted_since` опирается на `started_at` диспетчера, его надо проверить после правки диспетчера.

## 6. Обрыв после `POST /prompt`

Клиент отправляет `POST /prompt` с `extra_data {client_id, studio_task_id}` и сам себя останавливает (SIGSTOP) до чтения ответа (остановка через 0,09 с). Перед этим идёт блокирующая H3-задача.
- Через 0,1 с задача в `/queue` как `queue_pending`, `extra_data.studio_task_id` виден; через 116 с в `queue_running`; через 138 с в `/history` (`status: success`, вывод узла 9). Везде тот же `prompt_id`, что клиент получил после `SIGCONT` (`5fbe8c9c-...`).
- Задача выполнилась без живого клиента и без WS.
- **Решение по исходу:** `find=exact` для ComfyUI подтверждён: ищем по `studio_task_id` в `extra_data` в `/queue` (`queue_running`, `queue_pending`: индекс 3 элемента) и `/history` (`prompt[3]`); ключ сохраняется. Ограничение из п. 5: история живёт в памяти процесса.
