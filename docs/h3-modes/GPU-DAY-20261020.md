## 7. Прогресс

- **sglang, tqdm в `serve-*.log`** (`logs/serve-panel-20261020-151756.log`, `logs/gpu-day-20261020-serve-fl2va.log`). tqdm пишет через `\r`, строка склеена с логом доступа uvicorn (`...GET /v1/videos...` на той же физической строке). Примеры:
  - `minimax_h3 denoise:   0%|          | 0/19 [00:00<?, ?it/s]`
  - `minimax_h3 denoise:   5%|▌         | 1/19 [00:13<04:03, 13.53s/it]`
  - `minimax_h3 denoise:  16%|█▋        | 8/49 [...]` (50 шагов)
  - 20 шагов дают счётчик из 19, 50 шагов из 49 (N-1). Финал `49/49`.
  - Помимо денойза в логе есть `Loading required modules:` и `Warmup requests:`; ещё один бар 100% `1/1` после денойза.
- **Как парсить надёжно:** читать хвост лога, `split("\r")`, брать последнюю часть с `denoise:`, регулярка `denoise:\s+(\d+)%\|[^|]*\|\s*(\d+)/(\d+)`; относить к текущей задаче по времени (`[date time] MiniMaxH3DenoisingStage started...` до `finished in`), так как в логе нет id задачи; при нескольких задачах подряд бар начинается с 0/N заново. Фаза до денойза (текстовый энкодер, ~1 мин) и после (VAE) счётчика не имеет; в `/v1/videos` поле progress не меняется до конца.
- **ComfyUI WS** `ws://127.0.0.1:8189/ws?clientId=...`: сообщения `{"type":"progress","data":{"value":N,"max":20,"prompt_id":"...","node":"11"}}` (node 11 = SamplerCustomAdvanced, по одному на шаг, value 1..20 при 20 шагах), `executing` с `node` (смена узла, `node:null` = конец), `execution_start`, `execution_cached`, `progress_state`. Пример: `{"t":2.79,"type":"progress","data":{"value":1,"max":20,"prompt_id":"2a9b5f84-...","node":"11"}}`. Есть `prompt_id`, значит привязка к задаче надёжная. Сырые журналы: `outputs/gpu-day-20261020/comfy/*.ws.jsonl`.
- **Решение по исходу:** Н7 закрыт: для ComfyUI прогресс берётся из WS (по prompt_id), для sglang из tqdm в логе диспетчера (ручка `/status.progress`: значение N/M по последнему бару, привязка по времени старта), в обоих случаях только на этапе денойза.
