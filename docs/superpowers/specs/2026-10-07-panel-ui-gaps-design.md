# Монтажная панель, волна 1.5: владелец проходит конвейер сам — дизайн

Дата: 2026-10-07. Ветка: `feat/panel-ui-gaps`. Основа: аудит
`~/worktrees/battle/ui-audit/REPORT.md` (07.10), обходы боя `~/worktrees/battle/run_battle.sh` и
`~/worktrees/battle/fixed/run_fixed.sh`, спека волны 1
`docs/superpowers/specs/2026-10-06-panel-on-alex-neuro-design.md` (дальше «спека W1»), IA волны 2
`docs/design/2026-10-panel-audit/IA.md` и макет `mockups/variant-a`.

## 1. Зачем

Боевой прогон 07.10 прошёл только через `curl` и `ssh`: проект создавался запросом, сценарий —
`PUT /scenes` из файла, сид — правкой `project.json` под `flock` по ssh (`run_fixed.sh`, шаг 5).
Аудит UI подтвердил: в браузере владелец не может создать видеопроект на sglang, задать сцены без
LLM, сид, стартовый кадр сцены 0, а LLM-путь доступен только обходом. Волна 1.5 закрывает это
**в текущей вёрстке**, минимально и аккуратно. Редизайн — волна 2.

**Критерий готовности (единственный):** координатор в браузере (playwright, без ssh/curl/правки
файлов) проходит новый проект 2–3 сцены × 3–5 с: референсы → проект → сценарий → сцены → апскейл →
сборка → «Скачать» финал (задача приёмки в плане).

## 2. Что не делаем

- Редизайн, новую навигацию, страницы проекта с адресом — это волна 2 (IA §1–2).
- Клип под трек (kind=clip) и песни на sglang — не трогаем, только не ломаем.
- Регулировку силы апскейла — только показ (сила считается по движению, `ltx.py:237`).
- Встроенные подтверждения вместо `window.confirm` (IA §1.6) — в 1.5 остаётся `confirm`, как во
  всём старом интерфейсе; текст обязан называть последствие («пересчитает сцены #1, #2»). Пересъёмка —
  исключение: у неё встроенная панель, потому что ей нужны поля (промпт, сид).

## 3. Принципы, чтобы волна 2 забрала работу без переписывания

1. **Поведение — в JSON-API** (инвариант спеки W1 §10). Всё, что UI запрещает, сервер запрещает
   тем же правилом и тем же текстом; UI лишь заранее гасит кнопку и показывает причину.
2. **Каждый новый кусок разметки — экспортируемая чистая функция `app.js`** (`export function
   …Html(data, ctx)`), без доступа к DOM и замыканию. Обработчики — тонкие, в DOM-половине. Волна 2
   переносит функции и заменяет только вёрстку вокруг.
3. **Имена — словарь IA/variant-a:** «+ Новый ролик» (в IA «+ Новый проект» → вид «Ролик»),
   «Пересчитать сцену», «Референсы проекта», «Апскейл LTX после сцен», «сила 0,6», «Чат по
   сценарию», «Скачать».
4. **Новые классы CSS — только на токенах `:root`** (`--card`, `--hairline`, `--fill`, `--ink*`,
   `--accent*`, `--fail*`, `--warn*`), без новых цветов; тёмная и светлая темы — автоматически.
5. **390 px:** у страницы нет горизонтальной прокрутки, у модалки проекта тоже; новые блоки
   складываются в одну колонку в `@media (max-width: 420px)`.

## 4. Внешняя зависимость: Task 0 (у другого агента, считается готовой)

API параллельного агента — закоммичено в ветке: `4005de38` (seed/steps сцены, seed проекта) и
`626db48d` (явные refs сцены); тесты `tests/test_sglang_scene_params.py`,
`tests/test_sglang_scene_refs.py`. Контракт по коду:

- `PUT /api/projects/<id>/scenes`: у сцены необязательные `seed` (int ≥ 0) и `steps`
  (int `sglang_args.MIN_STEPS..MAX_STEPS` = 2..100, только sglang; на MLX — 400).
- `PUT /api/projects/<id>/settings`: `{i2v_prefix?, seed?}`, `seed: null` снимает; хотя бы одно
  поле. В выдаче проекта — `project.seed` (`null` по умолчанию).
- Эффективный сид сцены: `scene.seed`, иначе `project.seed`, иначе 42
  (`assemble._first_set(..., SGLANG_DEFAULT_SEED)`); шаги: `scene.steps` или 50.
- **Явные референсы сцены:** `scenes[i].refs: ["@tag", …]` — только подключённые к проекту теги
  (иначе `unknown_tag`), неверный тег — `args_invalid`. Карточки из `refs` идут условиями **первыми**,
  без `<Subject N>` в тексте; `<Picture k>` считает сначала их картинки (`library.build_ref2va(...,
  extra_refs=...)`). Следствие для UI: сцена без `@`-тега, но с непустым `refs`, — не ошибка
  «нужен хотя бы один референс»; а владелец, пишущий свой `subject_definitions:`, должен знать, что
  `<Picture 1>` — первая картинка из `refs`.

## 5. Решения

### 5.1. Создание ролика и вход в диалог (аудит #2, топ-1)

На sglang зона «Сочинение» скрыта целиком (`app.js:2648`), а вместе с ней «Новый через диалог»
(`index.html:120`). В шапку зоны «Проекты» (`index.html:390`) добавляются две кнопки, видимые на
обоих движках:

- **«+ Новый ролик»** — `prompt()` названия (пустое = «Ролик ДД.ММ ЧЧ:ММ»), `POST /api/projects
  {kind:"video", title}`, затем сразу открыть модалку проекта. API есть (`web.py:4408`).
- **«Ролик через диалог»** — то же, что «Новый через диалог» в форме: `POST /api/chat
  {source:{kind:"new"}}` с пустым промптом и длительностью 10.

Пустая подпись `#projects-empty` меняется на «Проектов пока нет — «+ Новый ролик»».

### 5.2. Редактор сцен видеопроекта (аудит 3b, 4a–4d; топ-2, 3, 4)

Где: модалка проекта, `kind === "video"`, пока сценарий не ушёл в очередь — сервер пускает
`PUT …/scenes` только при `stages.scenes === "draft"` и `stages.script ∈ {draft,
awaiting_approval}` (`web.py:4292`). Тогда этап «Сценарий» показывает редактор вместо строки
«N сцен в сценарии». После утверждения — карточки сцен только для чтения (§5.6).

Сцена в редакторе (одна карточка `.scene-edit` на сцену, сверху вниз):

| Поле | Контрол | Правило |
|---|---|---|
| Промпт | `textarea.scene-edit-prompt`, **целиком**, без обрезки | непустой; на sglang — подсветка незнакомых/неверных `@`-тегов (`sceneTagIssues`, уже есть) и подсказка подключённых тегов кнопками, вставляющими тег в позицию каретки |
| Длительность | `input[type=number]` 3–15 с на sglang (5–10 на MLX), шаг 0,5 | подсказка «на сетке: 5,125 с» — то же округление, что сделает сервер при утверждении (`web._snap_video_scenes_sglang`; на JS — зеркальная функция, сверка тестом с Python) |
| «Начать с чистого листа» | чекбокс, не у сцены 0 | `fresh_start` |
| Сид | число ≥ 0 или пусто + кнопка «случайный» | пусто = «по проекту: N» или «по умолчанию: 42» в `placeholder` |
| Шаги | число 2–100 или пусто, только sglang | пусто = «50» в `placeholder` |
| Референсы без упоминания | чекбоксы подключённых тегов, только sglang | поле `refs` Task 0 (§4); подсказка «их картинки идут первыми: <Picture 1…>» |
| Стартовый кадр (только сцена 0) | `select`: «без кадра», подключённые не-voice теги, текущий загруженный файл; кнопка «Загрузить кадр…» | `start_image`: `@tag` или путь из `POST /api/uploads`; миниатюра выбранного |

Кнопки сцены: «↑», «↓», «Удалить» (не у единственной). Под списком: «+ Сцена» (новая сцена
наследует длительность последней), «Сохранить сценарий», пометка «не сохранено». Сохранение —
`PUT …/scenes` со всем списком; ответ сервера — единственный источник правды (перерисовка из него).
«Утвердить сценарий» при несохранённой правке сначала сохраняет, потом утверждает; отказ
сохранения останавливает утверждение.

**Вставка готового сценария** (`<details>` «Вставить сценарий JSON»): поле + кнопка «Загрузить».
Принимается ровно тело `PUT …/scenes` (`{scenes, references?}`) или голый список сцен. Разбор на
клиенте только отличает «не JSON / не та форма» с понятным текстом; всё остальное проверяет
сервер. Если сцены уже есть — `confirm` «Заменить N сцен?». Это закрывает файлы вида
`battle-scenes-fixed.json`.

Сид проекта — поле в блоке «Настройки проекта» рядом с `i2v_prefix` (`PUT …/settings {seed}`),
с отметкой «сохранено ✓» после ответа (аудит 4e).

### 5.3. Библиотека референсов (аудит 1a–1d, баг превью)

- **Превью при загрузке страницы** (баг): `loadLibrary()` идёт раньше первого `/api/state`, `outdir`
  ещё нет, и `libraryCardsHtml` не строит `<img>`. Решение: карточки перерисовываются в `poll()`,
  когда `state.outdir` стал известен или сменился; миниатюры — 96×96 `object-fit: cover`, не в
  натуральную величину.
- **Новая версия с файлом:** у карточки поле файлов и кнопка «Новая версия» → `POST /api/uploads`
  на каждый файл → `PUT /api/library/<tag> {description, assets}` (API есть, `web.py:4234`).
- **Выбор версии при подключении:** `GET /api/library` отдаёт у карточки `versions: [{version,
  kind, description, assets, created}]` (по возрастанию). В «Референсах проекта» у каждой карточки —
  `select` версии (по умолчанию — подключённая, иначе последняя); «есть vN» остаётся подсказкой.
- **Удаление карточки:** `DELETE /api/library/<tag>`. Отказ `library_card_in_use` (409), если тег
  подключён **хотя бы к одному проекту** — с перечнем «название (id)»; иначе каталог карточки
  переносится в `<outdir>/library/.trash/<name>-<YYYYMMDDHHMMSS>/` (не стирается). Причина «любой
  проект, а не только активный»: пересъёмка и апскейл готового проекта снова собирают промпт из
  карточки (`library.build_ref2va`), и удалённая карточка сломала бы их через неделю, молча.
  Отключить карточку от готового проекта можно (§5.5 блокирует только идущий).

### 5.4. LLM-путь (топ-5)

- **Вход в чат проекта:** у видеопроекта со сценарием в `draft/awaiting_approval` — кнопка «Чат по
  сценарию». `POST /api/chat {source:{kind:"project", id}}` — новый вид источника: сессия запоминает
  `project_id`, а её `tags` заранее равны подключённым тегам проекта (LLM сразу получает блок
  «Reference tags»). В модалке чата кнопка «Сделать проектом» для такой сессии называется
  «Применить к проекту» и шлёт `PUT /api/projects/<id>/scenes` со сценами из ответа модели
  (`chat.project.scenes` → `{prompt, duration}`), затем открывает проект. Это и есть «чат внутри
  проекта» из IA, только в модалке.
- **Создание проекта из чата** (`POST /api/projects {session_id}`, `web.py:4478`) проверяет
  длительности по движку: на sglang 3–15 с, на MLX по-прежнему 5–10. И подключает к проекту теги
  сессии (`session.tags`, последние версии); тег, которого нет в библиотеке, — отказ
  `library_card_not_found` с именем тега, проект не создаётся.
- **Контекст модели:** в системный блок `## Context` добавляется строка `scene duration: 3–15 s`
  (sglang) или `5–10 s` (MLX), чтобы модель не писала 20 с.
- **Честная подпись провайдера:** `GET /api/providers` отдаёт у строки `shares_gpu: true|false|null`.
  Источник: ключ `shares_gpu` записи в `providers.json`; без ключа — `true` для `type:"llama-local"`
  и для `base_url` на `localhost`/`127.0.0.1`/`::1`/`host.docker.internal`, иначе `null`. Подписи:
  `true` — «делит видеокарту с H3: пока модель поднята, рендер ждёт»; `false` — «внешний провайдер —
  память этой машины не занимает»; `null` — «где считает провайдер, не указано (shares_gpu в
  providers.json)». Подпись «не занимает» больше не ставится по одному лишь `type`.

### 5.5. Идущий проект: что можно менять (аудит 4e, 5a, риск)

**Решение — запрет на сервере, а не предупреждение.** Пока у проекта есть задача в очереди
(`_project_active_job(proj, jobs) is not None`, тот же джойн, что у удаления), сервер отвечает
`project_running` (409, код уже есть) на `PUT …/references` и `PUT …/settings`. Галочка апскейла
(`PUT …/route`) запрещена только пока идёт задача апскейла или сборки: во время сцен её смена
безвредна, маршрут читается, когда все сцены готовы.

Почему не предупреждение: сцены сцеплены кейфреймом, `i2v_prefix` и референсы входят в промпт
каждой следующей сцены, а уже снятые не пересчитываются — проект молча получает две половины с
разным героем. Предупреждение, которое показывается на каждом клике, прожимают не читая (это уже
случалось с `confirm` в этой панели, см. комментарий `app.js` у Esc в чате). Выход есть: дождаться
конца (или падения) сцен, поменять, «Пересчитать сцену» с нужной — она переснимется с новыми
настройками. Для роликов в 2–5 сцен это минуты.

UI: поля и галочки в «Настройках проекта», «Референсах проекта» и «Апскейл LTX» при блокировке
`disabled`, под блоком строка `.lock-note` с причиной («Проект считается — референсы меняются после
конца прогона. Чтобы поменять для части сцен: дождитесь конца и пересчитайте с нужной сцены»).

### 5.6. Прогон, пересъёмка, кто держит карту (аудит 6b, 6e, 8b)

- **Прогресс на sglang без нулей.** У sglang-задачи нет MLX-проходов и `runs`; `estimate` —
  `{seconds, source, samples}` (`assemble.py:1420`). Карточка «идёт» на sglang показывает: имя
  (сцена и проект), канвас/длительность/сид/шаги из аргументов задачи, «идёт 3 мин 10 с из ≈9 мин»,
  долю по времени (не больше 99 %, пока задача не кончилась), «кончится ≈ЧЧ:ММ»; ячеек «Проход» и
  «Пик памяти» нет. Пока задача ждёт карту (`wait_reason`), вместо доли — «ждёт карту», причина в
  плашке GPU.
- **Плашка «кто держит карту» во время прогона.** Сейчас при `running` без `wait_reason` плашка
  пуста (`gpuBanner`, ветка `own.length && !run`). Новое: «Карту держит панель: H3 считает
  «<проект>», сцена #N — 4 мин, 41,0 ГБ»; если задача взята, а своего движка ещё нет — «H3
  поднимается для «<проект>», сцена #N».
- **Пересъёмка с правкой.** `POST …/scenes/<idx>/retry` принимает необязательное тело `{prompt?,
  seed?, steps?}`, проверенное теми же правилами, что `PUT …/scenes`, и записанное в сцену под
  тем же замком, что инвалидирует хвост. Пересъёмка не снятой сцены (`pending`) — отказ
  `project_stage_not_ready` «сцена #N ещё не снималась». В UI «Пересчитать сцену» есть только у
  `done`/`failed`; по клику под карточкой открывается панель: промпт целиком, сид (текущий
  эффективный в `placeholder`) + «новый случайный», шаги (sglang), строка каскада «пересчитает
  #1, #2, #3» (то же правило остановки на `fresh_start`, что `invalidate_scene_chain`),
  «Пересчитать» / «Отмена». В теле уходят только изменённые поля.
- Карточка сцены после утверждения показывает промпт **целиком** в `<details>` (первые 260
  символов — в `summary`), эффективный сид и шаги.

### 5.7. Апскейл и сборка (аудит 5b, 7a–7c, баги)

- `GET /api/projects/<id>` отдаёт `upscale_report`: `{status, strength, motion, parts:[idx…],
  error}` из `<project>/upscale/report.json` или `null`. В блоке апскейла: «Апскейл LTX: готов ·
  сила 0,6 · 3 из 3 частей»; при `failed` — текст ошибки и «Повторить апскейл» (есть).
- У карточки сцены с `ltx_path` — ссылка «LTX» на апскейленную часть.
- **404 job-upscale в «Готово»:** плитка задачи `upscale project <id>` строит ссылку на несуществующий
  `job-upscale.mp4`. Такие задачи прячутся из «Готово» тем же фильтром, что сцены и трек
  (`isProjectPipelineNote`); результат апскейла живёт в проекте.
- **«Скачать»** рядом с `final.mp4`: `<a download="<название>-final.mp4">`.
- **«Черновая сборка»** только когда все сцены `done` и сборка не `running` (сервер уже отказывает,
  `web.py:3586`, — кнопка больше не обещает того, чего не будет).
- У плиток сборки проекта в «Готово» нет «Обсудить» и «Копия» (аудит: чат с финала предлагал
  «обновить задачу»).

### 5.8. CSS

Своих правил сейчас нет у `#library`, `.lib-card`, `.project-settings`, `.project-refs`,
`.route-upscale`, `.upscale-status`, `.tag-warnings`, `.muted` (проверено `grep` по `style.css`

## 7. Тестирование

- Серверное — `_call` против живого `_serve` (как `tests/test_sglang_scenario_load.py`), точным
  равенством тел и файлов на диске.
- UI — чистые функции через `_node_eval` с точным равенством строк разметки; проводка DOM — через
  сценарии node-харнесса (`tests/_ui_harness.mjs` + `tests/_ui_gaps_check.mjs`) с моками, где
  `closest`/`match` сравнивают селектор строго (`===`), без `.includes()` (память проекта: три
  выжившие мутации за два дня).
- Каждый тест увиден красным мутацией защищаемой строки (CLAUDE.md); ошибка утверждения — в
  отчёт задачи.
- Сверка двух реализаций одного правила (сетка длительностей, каскад пересъёмки) — тестом, который
  гоняет таблицу входов через Python и через node и сравнивает.
- Приёмка — живой проход в браузере (§1).

## 8. Риски и открытое

- Нумерация `<Picture k>` с явными `refs` (сначала `refs`, потом теги текста) неочевидна
  владельцу, который пишет свой `subject_definitions:`; в 1.5 — только подсказка под полем `refs`.
- `shares_gpu` на alex-neuro зависит от `base_url` Qwen в `providers.json`; если там IP хоста, нужен
  явный ключ — правка конфига на сервере при выкладке (делает координатор, не код).
- Гонка «удаление карточки ↔ подключение к проекту в ту же секунду» не закрыта замком: подключение
  после переноса получит `library_card_not_found`, а проект, подключивший карточку между проверкой и
  переносом, увидит ту же ошибку на постановке сцены. Для одного владельца приемлемо.
- `window.confirm` против встроенных подтверждений IA — сознательный долг до волны 2.
