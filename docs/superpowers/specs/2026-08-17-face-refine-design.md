# Боевой face-refine — спека

**Дата:** 2026-08-17. **Статус:** дизайн утверждён пользователем. **Ветка:** main.
**Основание:** docs/FEASIBILITY-face-refine.md + три раунда экспериментов (секции
«Эксперимент 2026-08-17», «Раунд 2», «Раунд 3» там же). Все параметры ниже — измеренные,
не гипотезы.

## Что строим

Проход «улучшить лица» по готовому ролику: находит лицо, вырезает, прогоняет v2v-рефайн
дистиллированной моделью при малой sigma, вклеивает обратно. Лечит мыльные мелкие лица
(40–80 px), НЕ лечит сломанную анатомию — деформация станет резкой деформацией.

Продуктовая форма (выбор пользователя): **кнопка на готовом ролике** в «Закончилось» +
CLI-команда как ядро. Галочки в форме постановки нет.

## Зафиксированные параметры (из экспериментов)

| параметр | значение | откуда |
|---|---|---|
| sigma | 0.25 по умолчанию, потолок 0.25 (диапазон 0.15–0.25) | R2: выше — сочинение выражения и «гравюра» |
| окно | 56 кадров (17·3+5, нативная сетка, 17 латент-кадров) | R1 |
| шаг окна / перекрытие | ~40–44 / 12–16 кадров | R3: −35% GPU против шага 28 |
| кроссфейд | ≥12 кадров, по декодированным пикселям | R3: лечит стык полностью, гостинга нет |
| кроп | ×2.5–3 вокруг лица → лансцош до 448×288 | R2 |
| рамка кропа | функция номера КАДРА, не окна | R3: иначе рассыпается ко-регистрация окон |
| аудио v2v | чистый шум (реальное аудио не энкодить) | R1: различие в пределах шума |
| таблица AdaLN | партиальная, 3–4 точки, turbo LoRA 1.0 вбейкана; автобейк при отсутствии (0.7 с CPU, 87 МБ) | R1 |
| seed | фиксированный на весь проход (оба окна одним сидом) | R3 |
| края окна | не обрезать (краевых эффектов нет) | R3 |
| стоимость | ~2.1 мин/окно, пик 28.4 ГБ (текстовый энкодер) | R1–R3 |

Референс-реализация механики v2v: `~/Research/TestVideo/face-refine-exp/v2v_face_refine.py`
(+ `round2/v2v_r2.py`, `round2/overlap/crossfade.py`, `bake_partial.py`) — рабочие скрипты
экспериментов, механика оттуда переносится в модуль, не переизобретается.

## Архитектура

### Ядро: `h3_48gb/facerefine.py`
Вход: путь mp4 + параметры (sigma, размеры окна — всё с умолчаниями из таблицы выше).
Конвейер: детект → трек → кроп → окна v2v → кроссфейд → вклейка → сборка mp4.
Аудио копируется из исходника нетронутым (ffmpeg `-c:a copy`).

### Детекция и трек: `h3_48gb/facetrack.py`
- YuNet (`cv2.FaceDetectorYN`) — единственная новая зависимость: ONNX-файл ~300 КБ из
  opencv_zoo (`face_detection_yunet_2023mar.onnx`), кладётся в `~/models/yunet/`,
  в коде — честная ошибка с URL, если файла нет (по образцу checkpoint_not_found).
- Детект раз в N кадров (N=5) + линейная интерполяция + savgol-сглаживание центра/размера;
  рамка — функция кадра. Кадры без детекта: рамка экстраполируется, вклейка с fade_out
  (рецепт из README ComfyUI-FaceRefine: paste только face-box, прямоугольник лучше
  SAM-маски, fade_out на кадрах без детекта).
- Этап 1: одно лицо за проход — самое крупное по медиане площади детектов.

### Вклейка: в `facerefine.py`
Даунскейл результата обратно к размеру рамки, вклейка по растушёванной маске
(прямоугольник с мягкой рамкой ~10% стороны). Границы кадра — клип рамки.

### Задача очереди и веб: `kind: "face-refine"`
- `POST /api/jobs/<id>/face-refine` → submit в существующую очередь задачи с args
  `["face-refine", "<путь mp4>", ...]`; воркер запускает как обычную задачу (тот же
  лизинг/пауза/LLM-гейт). Никакого нового механизма очереди.
- Результат: `<стем исходника>-faces.mp4` в той же папке задачи; в «Закончилось» —
  отдельная строка (обычная задача очереди).
- Кнопка «улучшить лица» в карточке готовой задачи, в confirm — оговорка «чинит мыльные
  мелкие лица, не чинит сломанную анатомию» + оценка времени (~6 мин GPU на лицо на 5 с).
- Оценка длительности: (число окон) × 2.2 мин + декод; окна считаются из длины ролика.

### Идентичность чекпойнта
`checkpoint_identity_extra()` прохода несёт: digest исходного mp4, sigma, сетку окон,
версию рамки трека — чтобы резюме прохода никогда не спуталось с резюме генерации
(класс ошибок, который h3_48gb/checkpoint.py исключает везде).

## Этапность

**Этап 1 (CLI-ядро):** facetrack + вклейка + оконный v2v-движок + `h3 face-refine <mp4>`.
Ворота: интеграционный прогон на sovi-s1 (источник раундов 2–3) даёт результат не хуже
эксперимента; отдельная проверка на трекинг-кропе с сильным движением (centaur-official,
источник 2 раунда 2) — остаточный риск R3.

**Этап 2 (веб):** маршрут + kind + кнопка + оценка. Ворота: полный прогон тестов + смоук
на тестовом порту 18765.

## Вне рамок

- Несколько лиц за проход (расширение потом, если понадобится).
- Автодетект «нужен ли рефайн» (решает человек кнопкой).
- Галочка в форме постановки задачи.
- Ускорение декода, кеширование шагов — отдельные пункты бэклога.

## Риски

- Трекинг-кроп на сильном движении не проверен в R3 (там статичная камера) — закрывается
  воротами этапа 1.
- YuNet может не задетектить совсем мелкие/повёрнутые лица — тогда проход честно
  сообщает «лиц не найдено» и не портит ролик (выход = исходник не создаётся вовсе,
  задача завершается с этим сообщением).
- Geometry drift: латент-геометрия окна выводится из формы кропа, не из duration — та же
  мера, что в экспериментах (56 = 17·3+5), плюс shape-тест.
