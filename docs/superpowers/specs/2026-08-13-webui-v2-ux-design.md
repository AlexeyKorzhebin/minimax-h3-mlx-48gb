# Веб-морда v2: UX по итогам ручной проверки

**Дата:** 2026-08-13. **Ветка:** `h3-web` (продолжение). **Источник:** ручной прогон
пользователя по сценарию «текст → видео»; 13 замечаний + 4 решения из обсуждения.

## Решения из обсуждения

| вопрос | решение |
|---|---|
| разрешения | выпадающий список: черновик/малое/большое × горизонталь/вертикаль + пункт «своё» с ручным вводом; кнопки-пресеты уходят |
| старт очереди | очередь получает состояние «приостановлена» (по умолчанию): задачи накапливаются, работник не берёт; кнопки «начать расчёт» / «приостановить» на всю ленту; текущая задача при паузе доигрывает |
| имена | LLM в том же JSON-ответе диалога отдаёт короткий slug — он становится тегом, именем папки и файла (`ДатаВремя-слаг`); без диалога — эвристика (первые значимые слова промпта транслитом + время); модель ради имени не поднимается никогда |
| дизайн | полный дизайн-проход: сначала 2–3 макета структуры страницы на выбор пользователю, потом реализация по выбранному |

## Замечания и что делаем

### Диалог (модалка)

1. **Очистка истории.** Кнопка «очистить» в модалке (стирает ленту и промпт текущей
   сессии после confirm) + список сессий с удалением: `DELETE /api/chat/<id>` (файл
   сессии и его `.lock` удаляются — снимается и отложенный минор про осиротевшие локи).
2. **Индикация работы LLM.** Пока ход в полёте: анимированная плашка со стадией —
   «поднимаю модель…» (из статуса), «модель думает…» (после ensure_up), плюс
   анимированные точки в ленте на месте будущего ответа. Кнопка «отправить» уже
   блокируется — оставить.
3. **Очистка поля ввода.** Текст очищается сразу при отправке; при ошибке хода —
   возвращается в поле (сохранить текущее поведение возврата, убрать только
   «висящий» текст при успешном ходе — сейчас он очищается только после ответа).
4. **Длительность в модалке.** Поле «длительность, с» в шапке модалки (по умолчанию —
   из формы/задачи-источника); уходит в контекст LLM (`## Context: duration: N s`),
   чтобы разбивка `[Shot N]` таймилась по реальному хронометражу; живой разбор в
   модалке использует её же (снимается отложенное замечание про длительность из формы).
5. **Картинка в диалог.** В поле ввода чата: drag&drop картинки и кнопка-скрепка
   (файловый диалог). Приложенная картинка уходит ходом к зрячей модели («опиши и
   сделай промпт»); сессия автоматически получает `mode: i2v` и путь кадра
   (файл копируется в `<outdir>/chat/uploads/`), режим подставляется в форму при
   «в Редактор».

### Форма постановки

6. **Файловые поля.** Вместо текстовых путей («Первый кадр», «Последний кадр»,
   чекпойнт/LoRA/таблица — где уместно): зона drag&drop + стандартный `<input type=file>`.
   Сервер принимает загрузку (`POST /api/uploads`, файл ложится в
   `<outdir>/uploads/`, путь подставляется в поле). Ручной ввод пути остаётся как
   fallback (продвинутый режим).
7. **Разрешения выпадашкой** (решение выше), включая вертикальные: 288×448, 576×896,
   768×1344. Оценка стоимости пересчитывается как раньше.
8. **Коллапс настроек.** «Настройки модели» (чекпойнт, LoRA, сила, таблица AdaLN,
   шаги, сид) сворачиваются в `<details>`-блок, по умолчанию свёрнут — рецепт зашит
   умолчаниями, разворачивают редко.
9. **Поле «Заметка»** — убрать с формы (в очереди колонка примечания остаётся, если
   где-то используется; проверить и, если мертва, убрать сквозняком).

### Очередь и результаты

10. **Пауза/старт очереди** (решение выше): `POST /api/queue/pause`, `POST /api/queue/start`,
    состояние в `/api/state`; работник уважает флаг (файл-маркер в корне очереди —
    переживает рестарты). Плашка выгрузки LLM показывается только когда очередь
    запущена.
11. **Папка на задачу.** Результаты задачи ложатся в `<outdir>/<ДатаВремя>-<слаг>/`
    (mp4, wav, json, превью). Слаг — из решения про имена. Ссылки в «Закончилось»
    ведут в папку задачи.

### Общий вид

12. **Адаптивность.** Страница не должна ломаться от ~360px до широких экранов:
    сетки на minmax/auto-fit, ряды кнопок переносятся, таблица очереди скроллится
    внутри себя. Кнопки пресетов больше не разъезжаются (их и нет — выпадашка).
13. **Дизайн-проход** (решение выше): отдельным этапом — 2–3 статичных HTML-макета
    структуры (иерархия: «что я хочу сделать» → «что считается» → «что готово»;
    типографика, отступы, тёмная тема как сейчас), показать пользователю, выбранный
    реализовать. Функциональность п.1–12 не ждёт макета там, где не завязана на
    вёрстку (API, слаги, пауза очереди — делаются сразу).

слаг в JSON-схеме диалога.
Этап B (дизайн): ✅ выполнен 2026-08-13 через 花叔Design — три независимых макета
(нео-брутализм / школа Linear / Рамс-Braun), пользователь выбрал **школу Linear**:
`docs/superpowers/design-demos/variant-reference.html` — канонический макет реализации
(лестница тёмных поверхностей #08090a→#18191a, волосяные границы, Inter 400–590 без
жирного, единственный янтарный акцент #e0a33e только там, где GPU считает, инверсная
светлая главная кнопка, JetBrains Mono с tabular-nums для промпта/путей/цифр).
Дополнительно: **светлая тема** на той же базе через CSS-токены —
`variant-reference-light.html`; реализация обязана строить обе темы на одном наборе
custom properties с переключателем (и уважать prefers-color-scheme по умолчанию).
Этап C (вёрстка по выбранному макету): 5, 6, 7, 8, 12 + перенос этапа A в новую сетку.

## Вне рамок

- Проекты (мульти-клиповые сценарии) — прежняя отдельная спека.
- Аутентификация/доступ извне — страница остаётся локальной.
- Миграция старых плоских результатов в папки — не трогаем, новое правило только
  для новых задач.
