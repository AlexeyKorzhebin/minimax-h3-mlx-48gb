Дата: 2026-10-09. Статус: черновик для владельца. Это не спека и не макет. Это вход для добивки
макета A и для спеки клиента (д).

Основа:

- `docs/panel/2026-10-07-ui-audit/REPORT.md`.

**Рамки.**
- Пользователь один, это владелец.
- Продукт — ролик из нескольких сцен (Р3).
- Одиночный прогон — это проект из одной сцены (Р5).
- Всё делается в UI, без ssh и curl.
- Ширина 390 px обязательна (Р7).

**Обозначения.**
- `fl2va` и `ref2va` — варианты сервера H3. Один сервер держит один вариант, смена занимает около 2,5 мин (Режимы §2.1).
- «ч» — человек, «с» — система.
- Времена взяты из замеров Режимы §2.2 и RESULTS.md. Пометка **(экстр.)** — экстраполяция, не замер.

## 0. Сквозные правила, которые делают путь безопасным

| # | Правило | Зачем |
|---|---|---|
| П1 | Состояние проекта, сцен, чата и **предложенных чатом сцен** хранится на сервере (SQLite). Любое поле редактора сохраняется само через ~1 с. Кнопки «Сохранить» нет. | Закрыть вкладку без потерь (Н8, ветка 3.4). |
| П2 | Одно поле ввода в чате. Других полей, «уходящих в модель», рядом нет. | Н1. |
| П3 | Режим сцены — явное поле у каждой сцены (Р9). Вариант сервера выводится из режима, человек его не выбирает. | Н3. |
| П4 | Проверка ввода идёт в момент правки, у поля. Кнопка постановки неактивна, и рядом написано почему. Сервер повторяет ту же проверку (правило живёт на сервере, DRAFT §2д). | Режимы §2.1: сервер принимает неверную задачу, она падает через секунды. |
| П5 | У сцены есть «отпечаток входов»: режим, текст, референсы с версиями, кадры, сид, шаги, длительность, формат. Пока отпечаток не изменился, готовый клип сцены не сбрасывается. | Н9. |
| П6 | Оценку времени и прогресс считает только сервер. Прогресс берётся из счётчика шагов движка, а не из таймера. Оценка считает холодный старт и смены варианта. | Н7. |
| П7 | Необратимое подтверждается встроенно, с последствием («пересчитает #3 и #4, ≈ 22 мин»). Для удалений есть «Отмена 5 с». | IA §1.6. |

## 1. Основной путь: от идеи до скачанного ролика

Пример для оценок — ролик 4 × 8 с (32 с), 896×512 (16:9). Сцена 1 идёт в режиме «Референсы» (`ref2va`), сцены 2–4 — «От кадра» (`fl2va`).

### Этап 1. Идея
- **Человек:** «Проекты» → «+ Новый проект». Пишет идею в одно поле. Задаёт формат кадра (16:9 / 9:16 / 1:1 / 3:2 / 2:3) и целевую длину ролика.
- **Видит:** форму из трёх полей и кнопку «Создать и обсудить». Вид проекта «Ролик» стоит по умолчанию: клип будет в волне 3, сейчас вид не выбирается.
- **Система:** создаёт проект (адрес `#/projects/<id>/idea`). Отправляет идею первым сообщением в чат проекта. Формат кадра фиксирует на проект.
- **Ошибки и защита:** пустая идея — кнопка неактивна с подписью «напишите идею». Формат после первого готового клипа не меняется: поле заблокировано, рядом причина.
- **Ожидание:** мгновенно.

### Этап 2. Кастинг и референсы
- **Человек:** в шаге «Кастинг» нажимает «+ Референс». Загружает фото с диска или телефона, либо выбирает из библиотеки. Указывает роль: человек / место / предмет / стиль / голос / трек. Пишет описание по-русски.
- **Видит:**
  - два списка: «В проекте» и «Можно подключить из библиотеки» (свёрнут);
  - у карточки — `@тег`, версию, превью;
  - **английский текст, который уйдёт в H3**, его можно править;
  - у аудио — выбор «голос/тембр · фон · точный трек».
- **Система:**
  - создаёт карточку в библиотеке и сразу подключает её к проекту с фиксированной версией;
  - переводит описание через LLM;
  - для медиа проверяет длительность 2–15 с и сумму по типу до 15 с (Режимы §2.7).
- **Ошибки и защита:**
  - фото портретное, а формат проекта альбомный — предупреждение у карточки: «как кадр в ref2va не сработает» (Режимы §2.4);
  - аудио длиннее 15 с — отказ у поля;
  - кириллица в английском тексте подсвечивается.
- **Ожидание:** загрузка — секунды. Перевод — около 5–20 с (не мерили).

Шаг можно пропустить: ролик целиком по тексту референсов не требует.

### Этап 3. Сценарий со сценами
- **Человек:** обсуждает в боковом чате проекта. Просит, например, «разбей на 4 сцены по 8 с». Правит словами. Нажимает одну кнопку «В проект (4 сцены)».
- **Видит:**
  - ответ модели — **список карточек сцен**: № / длительность / режим / текст / `@теги`, а не один текст;
  - перед применением — diff против текущего сценария: «+2 новых, #1 без изменений, #2 текст изменён → сбросит клип #2».
- **Система:**
  - LLM (CAILA) получает текущие сцены проекта и карточки кастинга;
  - возвращает сцены с предложенным режимом;
  - сохраняет предложение в сессии чата на сервере.
- **Ошибки и защита:**
  - сцен в ответе нет — кнопка неактивна, подпись «модель не предложила сцен»;
  - длительности вне 3–15 с — сервер режет по сетке и показывает правку.
- **Ожидание:** ответ LLM ≈ 10–60 с (не мерили).

Сценарий можно писать и без LLM: «+ Сцена» в редакторе.

### Этап 4. Режим каждой сцены
- **Человек:** открывает сцену. Режим уже предложен, человек его подтверждает или меняет:
  - «Текст»;
  - «От кадра» / «К кадру» / «Между кадрами»;
  - «Референсы»;
  - «Референсы + кадр» (экспериментально).

  Для кадров выбирает источник: последний кадр предыдущей сцены / загрузить / из библиотеки.
- **Видит:**
  - поля, которые нужны именно этому режиму, и только их;
  - полоску «картинок в H3: N из 6»;
  - бейдж варианта: «быстро · fl2va» или «медленнее в 1,5× · ref2va»;
  - свёрнутый блок «Промпт для H3», только для чтения. Его формат зависит от режима, в `ref2va` до шести секций (Режимы §2.8).
- **Система:**
  - правило по умолчанию: сцена 1 с `@человеком` получает «Референсы», сцена-продолжение — «От кадра» последнего кадра предыдущей (Режимы §3);
  - сохраняет режим и отпечаток.
- **Ошибки и защита:**
  - `@тег` в сцене режима «Текст» или «От кадра» в модель не уходит. Предупреждение у тега и два действия: «Перевести сцену в Референсы» / «Вставить описание текстом»;
  - портретный кадр в `ref2va` запрещён (Режимы §2.4);
  - больше 6 картинок — нельзя добавить седьмую.
- **Ожидание:** мгновенно.

### Этап 5. Проверка ввода
- **Человек:** нажимает «К черновику» внизу шага «Сценарий».
- **Видит** сводку:
  - по каждой сцене ✓ или ✕ с причиной и ссылкой «исправить»;
  - **план очереди**: «ref2va: #1 → смена варианта ~2,5 мин → fl2va: #2, #3, #4»;
  - итоговую оценку черновиков и финала.
- **Система:** сервер прогоняет все проверки П4 и строит порядок. Внутри проекта сцены группируются по варианту, но порядок цепочки «от кадра» не нарушается (Р9).
- **Ошибки и защита:**
  - есть ✕ — кнопка «Поставить черновики» неактивна;
  - цепочка ссылается на сцену, которой ещё нет — ✕ с объяснением.
- **Ожидание:** меньше 1 с.

### Этап 6. Черновик, 20 шагов
- **Человек:** «Поставить черновики (4)». Дальше можно уйти: всё продолжится без открытой вкладки.
- **Видит:**
  - сцены по мере готовности (SSE, без перезагрузки);
  - у идущей сцены «шаг 12/20 · ≈ 2 мин»;
  - на плашке GPU — «поднимается ref2va ~2,5 мин» или «ждёт карту: <кто>».
- **Система:**
  - через диспетчер берёт карту и поднимает вариант;
  - продолжение «От кадра» ставит только после готового черновика предыдущей сцены, последний кадр берёт автоматически.
- **Ошибки и защита:**
  - задача упала — у сцены причина человеческим языком, хвост лога и «Повторить»;
  - карта занята чужим процессом — это ожидание, а не ошибка.
- **Ожидание** для примера ≈ 25–30 мин (экстр.):
  - холодный старт 3 мин;
  - ref2va 8 с × 20 шагов ≈ 6,5 мин (экстр. от 50 шагов);
  - смена варианта 2,5 мин;
  - 3 × fl2va 8 с × 20 шагов ≈ 4–4,5 мин (экстр.).

  Замер есть только для 3 с при 20 шагах: fl2va 65–80 с, ref2va ~150 с.

### Этап 7. Просмотр и правка
- **Человек:** смотрит каждую сцену. Может посмотреть «черновик ролика подряд» — склейку черновиков. По каждой сцене решает: «Годится» / «Пересъёмка с новым сидом» / «Править» (текст, режим, референсы).
- **Видит:**
  - дубли сцены, если их несколько: можно выбрать лучший;
  - перед пересъёмкой — каскад: «пересчитает #3, #4 (от кадра) · ≈ 9 мин».
- **Система:**
  - пересчитывает только сцены с изменённым отпечатком и продолжения от них;
  - остальные сохраняет (П5);
  - сид нового дубля пишет в сцену.
- **Ошибки и защита:** «Финал» неактивен, пока не все сцены отмечены «Годится», и рядом счётчик «3 из 4».
- **Ожидание:** пересъёмка одной сцены — 4–7 мин (экстр.).

### Этап 8. Финал, 50 шагов
- **Человек:** «Финал всего ролика». Или «Финал этой сцены» в меню «⋯» сцены.
- **Видит:**
  - план и оценку с учётом смен варианта;
  - предупреждение: «продолжения #2–#4 пойдут от финального кадра #1, кадр может немного отличаться от черновика».
- **Система:**
  - ставит финалы с теми же сидом и входами, steps=50;
  - цепочку ведёт строго по порядку;
  - после черновиков сервер стоит на fl2va, поэтому для #1 нужна смена на ref2va и обратно — это 2 смены.
- **Ошибки и защита:** как на этапе 6. Плюс: финал сцены, отпечаток которой изменился после «Годится», не ставится — сцена возвращается на этап 7.
- **Ожидание** для примера ≈ 55 мин:
  - смена варианта 2,5 мин;
  - ref2va 16 мин;
  - смена 2,5 мин;
  - 3 × fl2va 11 мин.

  Время сцен 8 с при 50 шагах замерено (Режимы §2.2).

### Этап 9. Сборка
- **Человек:** по желанию отмечает галочку «Апскейл LTX». «Собрать» запускается само, когда финалы готовы.
- **Видит:**
  - статус апскейла: «сила 0,6 · 3 из 4 частей»;
  - статус сборки.
- **Система:** апскейл пачкой, потом склейка и звук. Для аудио-карточки с ролью «точный трек» трек подкладывается после рендера (Р3).
- **Ошибки и защита:** сборка до готовых финалов невозможна — кнопки нет (аудит UI, баги).
- **Ожидание:** склейка — секунды. Апскейл не мерили для ролика.

### Этап 10. Результат
- **Человек:** смотрит. Нажимает «Скачать mp4», при необходимости «Скопировать путь».
- **Видит:**
  - плеер;
  - длительность, разрешение, размер;
  - список сцен с сидами;
  - «Переснять сцену» — возврат на этап 7 без сброса остальных.
- **Система:** отдаёт файл с поддержкой Range (просмотр на телефоне). Проект получает статус «Готово».
- **Ошибки и защита:** файл удалён с диска — вместо 404 сообщение «клип удалён, пересобрать?».
- **Ожидание:** мгновенно.

**Итого для примера:** около 1,5 ч машинного времени, из них ожидание человека — только этап 7.

**Не проверено** (это главный риск пути): совпадает ли композиция финала на 50 шагах с черновиком на 20 при том же сиде. Если не совпадает, черновик становится только эскизом, а этап 7 теряет смысл.
- Проверка: 3 сида × (20 и 50 шагов) × оба варианта, сравнить кадры 0/2/4/8 с.
- Делается до спеки клиента.

## 3. Ветки

### 3.1. Смешанный проект: ref2va (сцена 1) → fl2va (продолжения)
- План очереди показывает смены варианта и их цену заранее (этап 5).
- Порядок: #1 ref2va → смена → #2–#4 fl2va по цепочке. На черновиках 1 смена, на финалах 2.
- Возможная оптимизация (не решено): поставить финал #1 сразу после «Годится» для черновика #1, пока сервер ещё на ref2va. Экономит одну смену.
- **Не проверено:** узнаваемость лица после перехода ref2va → fl2va (Режимы §4; в C2 героиня спиной). Проба формата промпта ref2va идёт (`docs/h3-modes/BRIEF-prompt-format.md`). Пока нет результата, у продолжения висит пометка «лицо может дрейфовать: держите одинаковое описание героя».

### 3.2. Сцена «к кадру» и «между кадрами»
- Кадр можно взять так:
  - загрузить;
  - из библиотеки (роль «кадр/место»);
  - последний кадр предыдущей сцены (только для `[0]`).
- `[-1]` — всегда явный выбор человека.
- Проверки:
  - ориентация кадра совпадает с форматом проекта, иначе отказ у поля;
  - кадра в середине нет — такого поля и не появляется (Режимы §1).
- «Между кадрами»: оба кадра обязательны, рядом подсказка «модель интерполирует, сюжет — в тексте».
- Следующая сцена от кадра этой сцены получает её реальный последний кадр, а не загруженный `[-1]`.

### 3.3. Перегенерация одной сцены без сброса готовых
- «Пересъёмка» (новый сид) или правка → встроенное подтверждение с каскадом → в очередь только эта сцена и её продолжения «от кадра».
- Сцены в режимах «Текст» и «Референсы» не зависят от соседей: каскад пуст.
- Старый дубль сохраняется, к нему можно вернуться («Дубли: 2»).

### 3.4. Закрыл вкладку и вернулся
- Адрес шага в URL.
- Всё на сервере (П1): текст сцены (автосохранение), предложения чата, выбранные дубли.
- При возврате SSE отдаёт снимок и хвост событий, без перезагрузок.
- Набранное, но не дошедшее до сервера (обрыв сети), хранится в `localStorage` как запасной вариант. При возврате — «восстановить несохранённую правку сцены #2?».

### 3.5. Сервер упал / перезапуск варианта
| Событие | Что видит человек | Что делает система |
|---|---|---|
| Смена варианта | Плашка GPU «поднимается fl2va · ~2,5 мин», у сцены «ждёт сервер» | Диспетчер перезапускает. Задача ждёт и не падает |
| Сервер H3 упал во время сцены | У сцены «сервер перезапускается, сцена повторится», счётчик попыток | `reconcile` по `engine_ref`. 1 автоповтор, после второго падения — ошибка сцены |
| Ошибка сцены | Причина словами, хвост лога в UI, «Повторить», «Править» | Очередь идёт дальше по сценам, не зависящим от упавшей |
| Чужой процесс или Qwen держит карту | Баннер причины, «Выгрузить Qwen и начать» (только для Qwen) | Чужое не гасится, очередь стартует сама (IA §5) |
| Упала панель (web) | Плашка «нет связи, переподключаюсь» | Worker в своём контейнере продолжает. SSE переподключается и отдаёт снимок |

## 5. Вопросы к владельцу

1. **Финал продолжений.** Финал сцены «от кадра» идёт от финального кадра предыдущей сцены и может отличаться от черновика, который вы одобрили. Варианты:
   - (а) принять это;
   - (б) для продолжений не делать черновик, а снимать сразу финал после финала предыдущей.

   **Ставка:** (а), с предупреждением на этапе 8. (б) — опция «⋯ сразу финал» у сцены.
2. **Автоперевод на английский.** Описания карточек и тексты сцен переводить автоматически через LLM, показывая английский текст для правки? Или только подсвечивать кириллицу?

   **Ставка:** автоперевод с видимым и редактируемым результатом.
3. **Гибрид «Референсы + кадр».** Показывать в волне 2 под пометкой «экспериментально» или скрыть до проб?

   **Ставка:** показать, только с альбомным кадром и пометкой.
4. **Одиночный прогон.** «Проект из одной сцены» — тот же мастер (идея → сцена → черновик → финал), без шагов «Сценарий» и «Сборка»?

   **Ставка:** да, ярлык «+ Одна сцена» в «Проекты», без сборки.
5. **Перестановка в очереди.** Можно ли панели переставлять сцены по варианту сервера между разными проектами ради меньшего числа перезапусков?

   **Ставка:** только внутри проекта. Между проектами — порядок постановки.

**Решение владельца (2026-10-09):** все пять ставок приняты. Проба «черновик 20 против финала 50
при том же сиде» запущена: `docs/h3-modes/BRIEF-draft-vs-final.md`.

## 6. Что в этом черновике не проверено

- Совпадение финала на 50 шагах с черновиком на 20 при том же сиде (§1, главный риск).
- Время черновика 8 с при 20 шагах (экстраполяция). Время LLM-ответа и перевода. Время апскейла ролика.
- Источник счётчика шагов для прогресса (Н7).
- Предел референсов при 8–15 с (может быть ниже 6). Лицо после ref2va → fl2va. Формат промпта ref2va.
- Удобство на живом телефоне: макеты 390 px снимались в headless Chromium.
