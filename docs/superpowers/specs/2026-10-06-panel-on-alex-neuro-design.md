# Монтажная панель на alex-neuro — дизайн

Дата: 2026-10-06. Статус: согласован в диалоге, ревью не-автором пройдено (раунд 1, правки внесены),
ждёт чтения владельцем.

## 1. Зачем

Рендер на Маке (MLX) остановлен насовсем 01.10.2026 — слишком долго. Весь рендер идёт на
alex-neuro (CMP 170HX 64 ГБ): MiniMax H3 через sglang, апскейл LTX-2.5 через ComfyUI. Сейчас там
работают только скрипты (`pipeline.sh`, `newscene.py`), всё через ssh. Монтажная панель
(`h3 web` / `h3 worker` этого репозитория: проекты, чат, сценарий, сцены, очередь, сборка)
должна заработать на alex-neuro поверх этих движков и обновляться через Docker.

**Критерий успеха.** Владелец в браузере на Маке открывает `http://192.168.100.50:8765`,
создаёт проект из нескольких сцен, проходит путь «сценарий → сцены H3 → апскейл LTX → сборка» и
получает финальный ролик, ни разу не заходя по ssh. Все решения, которые раньше требовали ssh
(выгрузить Qwen, вернуть Qwen), — кнопки в панели.

## 2. Решения, принятые в диалоге

| Вопрос | Решение |
|---|---|
| Продукты v1 | `kind=video` (ролик) и `kind=clip` под **готовый** трек (импорт mp3). Генерация песен (Music3) и Whisper — не в v1 |
| LLM чата/сценария | как сейчас: `providers.json`, любой OpenAI-совместимый адрес (Qwen на alex-neuro :8000, llama-server на Маке, внешний API) |
| Qwen и H3 на одной карте | вместе не помещаются (Qwen shared32 `--mem-fraction-static 0.92`, пик H3 47–60 ГБ). Перед рендером панель показывает «Qwen держит карту — выгрузить?»; по нажатию владельца диспетчер делает `qwen.sh stop`. После очереди — кнопка «вернуть Qwen» (`qwen.sh start-shared32`), **только если Qwen был запущен до выгрузки панелью**. Сам, без кнопки, Qwen не трогается |
| Что в Docker | только панель (подход A). H3 и ComfyUI остаются на хосте в своих окружениях |
| Апскейл | пачкой после всех сцен проекта, одна сила LTX на весь клип; включается галочкой |
| Доступ | домашняя сеть, без пароля, порт 8765. Наружу не пробрасывается |
| Чужое на GPU | панель никогда не гасит чужое (Qwen Image, Krea2, ComfyUI, поднятый не диспетчером, другие лаборатории) — ждёт и показывает, кто держит карту; Qwen — только по кнопке; уважает `generation.lock` |
| Код | остаётся в этом репозитории; MLX-движок исключается из образа, но не удаляется |
| Цепочка сцен | через кейфрейм (+ референсы сцены); латентного переноса в sglang нет |
| Архитектура | сервисы за HTTP, панель — дирижёр; маршрут проекта из включаемых этапов; MCP — v2 |

## 3. Архитектура

```
Мак (браузер) ──http──▶ alex-neuro :8765
   ┌──────────────────── Docker: h3-panel (network_mode: host) ────────────────────┐
   │ web.py + webui           — как есть (+ разрешённые Host/Origin)               │
   │ queue / project / assemble / framecheck / runs — как есть (+ режим sglang)    │
   │ worker.py ── engine "sglang" (новый адаптер) ─────────────▶ H3 sglang :30020   │
   │            └ этап upscale (новый, HTTP ComfyUI) ──────────▶ ComfyUI LTX :8188  │
   │ provider.py (чат) ───────────────────────────────────────▶ LLM из providers.json│
   └───────────────┬────────────────────────────────────────────────────────────────┘
                   │ http 127.0.0.1:8790
   gpu-dispatcher (хост, systemd): поднимает/гасит СВОИ H3 и ComfyUI, видит чужое,
   держит generation.lock, выгружает/возвращает Qwen по кнопке
```

### 3.1. Сервисы

| Сервис | Ответственность | Где живёт | Версия |
|---|---|---|---|
| `panel` | UI, проекты, чат, очередь, маршрут, сборка ffmpeg | Docker | v1 |
| `gpu-dispatcher` | единственный, кто поднимает/гасит движки; GPU-статус для панели | хост, systemd | v1 |
| H3 (sglang) | рендер сцены | хост, `Projects/h3-bench/serve.sh` | как есть |
| LTX (ComfyUI) | апскейл | хост, `Projects/comfy` | как есть |
| LLM | чат и сценарий | любой адрес | как есть |
| `mcp` | инструменты для Hermes поверх API панели | Docker | v2 |
| аудио | генерация песни / озвучка | будущий сервис | позже |
| ai-writer | импорт сценария JSON-файлом | внешний | позже |

Не дробим саму панель: веб, очередь, сборка остаются одним процессом. Без брокера сообщений —
очередь файловая (`queue/{pending,running,done,failed}`, `os.rename` + `flock`). Без Kubernetes —
один `docker compose`.

### 3.2. Контейнер `h3-panel`

- База `python:3.12-slim` + ffmpeg + node (для `.mjs`-проверок фронта в тестах). Без CUDA, без
  `mlx`, `mlx-vlm`. `pyproject.toml` держит `mlx` жёсткой зависимостью (`pyproject.toml:13-14`) —
  в образе пакет ставится `pip install --no-deps .` + новый `requirements-panel.txt` (numpy,
  pillow, safetensors, jsonschema, pytest; без opencv/scipy).
- `network_mode: host` — видит движки и диспетчер на `127.0.0.1`.
- **Пути одинаковые в контейнере и на хосте.** sglang читает условия как `file:///home/alex/...`,
  поэтому тома монтируются по тем же путям:
  - `/home/alex/Outputs/h3-panel` (rw) — `H3_OUTDIR`: проекты, очередь, загрузки, видео,
    `providers.json`, `.env`;
  - `/home/alex/Outputs/comfy/output` (ro) — откуда забирать результат ComfyUI;
  - `/home/alex/Projects/h3-bench/inputs` (ro) — референсы, если нужны.
- Процессы: `h3 web --host 0.0.0.0 --port 8765` и `h3 worker` под простым entrypoint-скриптом
  (выход контейнера при падении любого), `restart: unless-stopped`.
- Пользователь в контейнере — uid/gid `alex` (1000).
- Окружение: `H3_ENGINE=sglang`, `H3_ALLOWED_HOSTS=192.168.100.50:8765,alex-neuro:8765`,
  `H3_SGLANG_URL=http://127.0.0.1:30020`, `H3_COMFY_URL=http://127.0.0.1:8188`,
  `H3_DISPATCHER_URL=http://127.0.0.1:8790`.
- Обновление: `git pull && docker compose build && docker compose up -d`. Данные на томе.

### 3.3. Что меняется в коде панели

1. **Движок как настройка.** `H3_ENGINE=mlx|sglang` (по умолчанию `mlx` — Мак не ломаем). Всё
   ниже, помеченное «при sglang», включается только этой настройкой.
2. **Аргументы сцены при sglang строит отдельная функция.** Сейчас `assemble._scene_generate_args`
   всегда добавляет `--turbo-strength`, всем сценам, кроме последней, `--save-latent-tail`, а
   сцепленной — `--latent` (`assemble.py:1192-1204`); общий парсер CLI подставляет MLX-умолчания
   (`--turbo-lora`, `--adaln-cache`, `--steps 8`, `cli.py:52-58`, `542-545`), и `RunSpec` в
   контейнере упадёт на `lora_not_found` (`cli.py:451`). Поэтому при sglang:
   - `assemble` строит argv через `_scene_generate_args_sglang`: prompt, `--width/--height`,
     `--duration`, `--steps` (по умолчанию **50**), `--seed`, `--tag`, `--outdir`, `--image`
     (кейфрейм), `--ref` (повторяемый, новый: картинки референсов сцены, уже разрешённые из тегов, §3.5), `--audio` (новый: кусок
     трека клипа), `--task` (`ref2va`|`t2va`, см. §4.1);
   - адаптер разбирает argv **своим** парсером (`h3_48gb/engines/sglang_args.py`), без
     `cli.py`/`RunSpec`. Любой флаг вне списка — отказ `unsupported_on_sglang: <flag>`;
   - тест отказа и тест приёма гоняются на argv, который реально строит `assemble`, а не на
     синтетическом.
3. **Адаптер `h3_48gb/engines/sglang.py`.** Выполняется в процессе воркера (не подпроцесс
   `python -m h3_48gb`). Артефакты: `<stem>.mp4`, `<stem>.json` (статус, `wall_s`,
   `inference_time_s`, `peak_memory_mb`, sglang `id`, payload). Превью по шагам нет.
4. **Валидация.** `web.validate_args` (`web.py:2350`) сейчас запускает подпроцесс
   `generate --dry-run` (`web.py:2397`). При sglang — вызов валидатора адаптера в процессе:
   известные флаги, холст из таблицы форматов (§4.1), длительность на сетке.
5. **Режим цепочки при sglang** (`assemble.py:42-54`, `322-338`, `1361-1376`):
   - кейфрейм — основной путь, а не запасной; латентного хвоста нет;
   - лимит `MAX_CONSECUTIVE_KEYFRAME_FALLBACKS` не применяется (кейфрейм — не откат);
   - перекрытие сцен = **1 кадр** (sglang повторяет кейфрейм кадром 0), `head_drop_frames = 1`
     для сцепленных сцен; `web._snap_scene_duration` (`web.py:904-918`) при sglang использует
     перекрытие 1 и сетку sglang (§4.1), а не 22 латентных кадра.
6. **Сеть.** Сервер панели принимает только Host `127.0.0.1:<port>`/`localhost:<port>`
   (`web.py:5820`, проверки `web.py:3114` Host и `web.py:3175` Origin), а `cli.py:618-620` прямо
   запрещает внешний bind. Добавить `--host` и список разрешённых `H3_ALLOWED_HOSTS` (Host и
   Origin сверяются с ним точным равенством). Внешний bind разрешён только вместе с непустым
   списком. Тест — запрос с `Host: 192.168.100.50:8765` и такой же Origin: проходит; с чужим
   адресом — `host_not_allowed`.
7. **Mac-специфика под условием:** `caffeinate` только на Darwin (`worker.py:83`, `204`); кнопка
   «Показать в Finder» скрыта не на Darwin; `pkill llama-server` только для `llama-local`;
   `_llm_holds_gpu` при sglang не используется — его роль берёт диспетчер.
8. **Маршрут проекта.** В проекте поле `route`: упорядоченный список этапов с флагом включения.
   v1: `scenario`, `scenes`, `upscale` (вкл/выкл, по умолчанию вкл), `track` (только для `clip`),
   `assemble`. Неизвестный этап — ошибка загрузки проекта, а не тихий пропуск. Существующие
   проекты без `route` получают маршрут по умолчанию своего `kind`.
9. **Библиотека референсов с тегами** (подробно — §3.5). Общая на все проекты, подключается к
   проекту. Сцены ссылаются на референсы тегами `@alice`, `@beach`; адаптер превращает их в
   формат Ref2VA (`<Subject N>`, `<Picture N>`, `subject_definitions`). Генератор сценария
   получает подключённые к проекту теги с описаниями и обязан расставлять их в каждой сцене.
10. **Клип под готовый трек без Whisper.** Сейчас импорт трека ставит задачу `song`
    (`web.py:4103-4110`, `4140-4142`), та вызывает `songrun.align_track` → `mlx_whisper`
    (`songrun.py:63`, `383`), а нарезка сцен опирается на `track.sections`/транскрипт
    (`web.py:1407…`, `1832-1843`). При sglang: импорт меряет длительность ffprobe и задачу `song`
    не ставит; сцены режутся по сценарию (LLM получает длительность трека и пишет сцены с
    длительностями; если их нет — равные куски), длительности снапятся к сетке (§4.1), последняя
    сцена добирает остаток. Транскрипт не используется.
11. **Новый вид задачи `upscale`** (рядом с `generate`, `song`, `assemble`), см. §4.2.
12. **Отмена задачи в `running`.** Сейчас `queue.cancel` работает только для `pending`
    (`queue.py:1257-1266`, `web.py:3765`). При sglang: «отменить» для `running` = перестать
    ждать (задача → `failed` с причиной `cancelled_by_user`, `DELETE /v1/videos/{id}` вызывается,
    но GPU он не останавливает — `video_api.py:821-827`; в UI честно: «H3 досчитает сцену
    впустую, следующая задача начнётся после»).
13. **Видимость ожидания (v1 — только в панели).** Когда очередь не движется (ждём GPU, Qwen,
    замок, перегрев), сверху на любой вкладке — плашка: сколько стоит, кто держит карту (имя
    процесса, pid, память, с какого времени), кнопка «выгрузить Qwen», если причина в нём. Пока
    вкладка открыта — браузерное уведомление (Notification API) на события: ожидание > 10 мин
    (повтор раз в час), сцена упала, проект готов, нужно решение. Внешние каналы (Telegram и т.п.) —
    не в v1, см. §8.
14. **Кнопка «Освободить карту»** в шапке, рядом с плашкой GPU, всегда видна:
    - очередь пуста → `POST /release` диспетчера сразу (свои движки гасятся, замок отпускается);
    - идёт рендер → подтверждение «H3 считает сцену N — освободить карту? Сцена будет потеряна»;
      после «да» задача → `failed` с причиной `released_by_user`, затем `release`;
    - после освобождения очередь ставится на **паузу** (существующий `/api/queue/pause`), иначе
      следующая задача сразу снова займёт карту; продолжение — «Продолжить очередь»;
    - чужое (включая Qwen) кнопка не трогает.
    Плашка показывает и обратное состояние: «карту держит панель: H3, 40 ГБ — освободится через
    12 мин или кнопкой».
15. **Оценки времени.** Калибровка под MLX неверна для сервера (сцена 560–3500 с). При sglang
    оценка берётся из медианы `wall_s` последних 10 сцен того же размера и длительности; пока
    истории нет — из таблицы по `results-*.jsonl` h3-bench (с пометкой «оценка»).

### 3.4. `gpu-dispatcher`

Скрипт `tools/gpu-dispatcher/dispatcher.py` в этом репозитории (stdlib), ставится на хост
systemd-юнитом, слушает `127.0.0.1:8790`. Команды запуска движков — как в
`Projects/h3-bench/pipeline.sh` (`serve.sh` с `VARIANT=ref2va` и TE nvfp4_awq, ComfyUI с
`--port 8188 --output-directory $COMFY_OUTPUT_DIR`). Логика остановки **не** переносится как
есть: `pipeline.sh` гасит `pkill -f` по шаблону и убил бы чужой ComfyUI/H3.

**Владение.** «Своё» — процесс, который запустил диспетчер: его pid и группа процессов хранятся
в `state.json` диспетчера (переживает рестарт диспетчера; pid сверяется с `/proc/<pid>/cmdline`,
чтобы не убить переиспользованный pid). Гасит только своё: SIGTERM группе, ожидание до 120 с,
SIGKILL группе. Всё остальное на GPU — чужое.

**Чужое.** По `nvidia-smi --query-compute-apps` и портам: H3 на :30020, которого диспетчер не
запускал; ComfyUI на :8188, которого он не запускал (там может быть Qwen Image или Krea2 —
пользоваться им для LTX нельзя); Qwen (`qwen38-sglang-dflash2-compose`); любые другие процессы.
Чужое не гасится и не используется.

**Вариант H3.** `h3_up` в `pipeline.sh` проверяет только `/v1/models`, а `serve.sh:11` по
умолчанию поднимает `fl2va`. Диспетчер считает свой H3 готовым, только если сам поднял его с
`VARIANT=ref2va`; чужой H3 на :30020 — чужое (ждать).

**`generation.lock`** — `/home/alex/Projects/qwen-image21-lab/generation.lock`, общий замок
GPU-работ на машине (им пользуются инструменты других лабораторий). Диспетчер берёт
`flock(LOCK_EX|LOCK_NB)` на время, пока свой движок поднят и работает, и отпускает при
`release`. Не взялся — `wait` с причиной «generation.lock занят». Замок `flock` снимается ядром
при смерти держателя, «протухшего» замка не бывает.

| Ручка | Поведение |
|---|---|
| `GET /status` | свои движки (что, pid, вариант, готов ли), чужое на GPU (pid, имя, память), Qwen (запущен ли, выгружен ли нами), `generation.lock`, температура и память GPU |
| `POST /acquire {"engine":"h3"\|"ltx"}` | нужный свой движок готов → `ready`. Чужое на GPU или замок занят → `wait` + причина (Qwen отдельно: `wait_qwen` — UI показывает кнопку). Иначе: гасит свой лишний движок, берёт замок, поднимает нужный, отвечает `starting`; клиент опрашивает `/status`; не поднялся → `failed` + путь к логу |
| `POST /release` | гасит свои движки, отпускает замок. Вызывается панелью: (а) по кнопке «Освободить карту» (§3.3.14); (б) автоматически, когда в очереди панели **нет ни одной задачи** (ни `pending`, ни `running`) 15 мин подряд (`H3_IDLE_RELEASE_MIN`). Отсчёт — от пустой очереди, не от простоя GPU: пока проект рендерится, карта не отдаётся |
| `POST /qwen/unload` | только по кнопке владельца: запоминает `qwen_was_running=true`, если Qwen был запущен, и делает `Projects/qwen/qwen.sh stop` |
| `POST /qwen/restore` | только по кнопке: если `qwen_was_running` — `release` своих движков и `qwen.sh start-shared32`, флаг сбрасывается; иначе — отказ «Qwen не был запущен до выгрузки» |

### 3.5. Библиотека референсов

Официальный формат Ref2VA (`Projects/h3-bench/skills/h3-prompt-writing/references/ref-en.txt`):
`<Subject N>` — любой переиспользуемый видимый объект (человек, предмет, костюм, окружение/фон,
стиль), его определение ссылается на картинки-источники `<Picture N>` (N — порядок картинки в
условиях); `<Audio N>` — референс голоса/музыки. Панель прячет эту механику за тегами.

**Модель данных.** `<H3_OUTDIR>/library/<tag>/`: `card.json` + файлы картинок/аудио.
- `card.json`: `tag` (`@[a-z0-9-]{2,32}`, уникален глобально), `kind`
  (`person|object|environment|style|voice`), `description` (1–2 фразы по-английски: что брать с
  картинки — внешность, одежду, место, свет), `assets` (1–4 картинки; для `voice` — один аудиофайл),
  `version` (растёт при каждой правке), `created/updated`.
- Правка карточки создаёт новую версию; старые файлы версии не удаляются, пока на неё ссылается
  хоть один проект.
- Проект хранит `references: [{tag, version}]` — подключённые карточки с **зафиксированной**
  версией: правка карточки не меняет уже отрендеренные сцены. Кнопка «обновить до последней
  версии» — явная, по карточке.

**Веб-клиент** (в волне 1 — простая рабочая форма в старом интерфейсе; полноценный вид ниже —
в волне 2, в новом дизайне, §10):
- Вкладка «Референсы» (глобальная): сетка карточек — превью, тег, тип; загрузка перетаскиванием
  (через существующий `POST /api/uploads`) или из уже загруженного; правка тега, типа, описания
  на месте; фильтр по типу; поиск по тегу.
- В проекте — блок «Референсы проекта»: подключить/отключить карточки из библиотеки, видна
  зафиксированная версия.
- В тексте сцены теги пишутся через `@`; на `@` — подсказка с превью из подключённых к проекту.
  Незнакомый тег подсвечивается ошибкой до постановки в очередь.
- Под сценой — полоска миниатюр: какие картинки уйдут в H3 и сколько из максимума (§4.1.3).

**Сценарий.** LLM получает список подключённых тегов (`tag`, `kind`, `description`) и обязана
указывать в каждой сцене, кто и где в кадре, тегами. Тег вне списка — ошибка валидации
сценария (как сейчас для схемы).

**Сборка промпта адаптером** (детерминированно, тестируется точным равенством):
1. теги сцены в порядке первого упоминания → `<Subject 1..K>`;
2. картинки этих карточек в том же порядке → условия `{"type":"image","role":"reference"}`;
   номера `<Picture N>` — по коду sglang (`stages/text_encoding.py:431-442`): кейфрейм **не
   нумеруется**, reference-картинки нумеруются с 1 в порядке условий, аудио — отдельно
   `<Audio j>`;
3. `subject_definitions`: строка на субъект — `<Subject k> is <description>, appearance from
   <Picture i>[, <Picture j>].`; для `voice` — `<Audio m>`;
4. в тексте сцены `@tag` → `<Subject k>`; остальной промпт — как пишет LLM/владелец.
Ограничение: не больше `H3_MAX_REF_IMAGES` картинок на сцену (в коде sglang предела нет, картинки
масштабируются до 2048 по короткой стороне — дорого по памяти; по умолчанию 6, проба уточнит); при
превышении — ошибка в форме сцены, а не тихое отбрасывание.

## 4. Поток данных

### 4.1. Сцена (этап `scenes`)

1. Воркер берёт `generate`, вызывает `acquire h3`. На `wait`/`wait_qwen` задача остаётся в
   `running` со статусом «ждём GPU: <причина>», повтор через 30 с; на `wait_qwen` в UI кнопка
   «выгрузить Qwen». Таймаута нет; отмена — §3.3.12.
2. Термозащита: температура из `/status` диспетчера (в контейнере нет `nvidia-smi`); ≥ 80 °C —
   ждать до 72 °C, статус «остываем, 81 °C».
3. Адаптер собирает `POST /v1/videos` по образцу `Projects/h3-bench/chain_beach.py` (8/8
   сцепленных сцен с кейфреймом и референсами прошли) и `runner_clip.py` (27 частей «Танго»):
   `model: "MiniMaxAI/MiniMax-H3"`, `prompt`, `task`, `conditions`, `target`
   (`short_edge`, `aspect_ratio`, `duration_seconds`), `num_outputs_per_prompt: 1`,
   `num_inference_steps`, `flow_shift: 12.0`, `audio_flow_shift: 3.0`, `seed`,
   `quality: "lossless"`. Условия:
   - **первая сцена блока** (первая или `fresh_start`): картинки референсов сцены (§3.5)
     (`{"type":"image","role":"reference"}`), `aspect_ratio` проекта;
   - **сцепленная сцена**: кейфрейм `{"type":"image","role":"keyframe","frame_index":0}`
     (последний кадр предыдущей) **плюс** картинки референсов сцены, `aspect_ratio: "auto"`, к промпту
     префикс `i2v_prefix` проекта;
   - **клип**: кусок трека сцены `{"type":"audio","role":"reference"}` добавляется к условиям;
   - **у каждой сцены должен быть хотя бы один reference** — `@`-тег с картинкой или (в клипе)
     кусок трека. Проба 07.10 на живом сервере (`Projects/h3-bench/logs/probe-t2va-20261007.log`):
     сервер, поднятый с `VARIANT=ref2va`, обслуживает **только** `ref2va` — `t2va` принимается
     (HTTP 200), но задача падает «task 't2va' is not served by MiniMax H3 partition 'ref2va'»;
     кейфрейм без reference — HTTP 400 «ref2va keyframes require at least one reference
     condition». Поэтому `task` всегда `ref2va`, а сцену без референса валидация отклоняет до
     очереди: «нужен хотя бы один референс (@тег) в сцене». Сцены без референсов (t2va/fl2va) —
     вне v1: это другой вариант сервера и перезапуск H3.
   Правила валидатора (код sglang, `model_specific_stages/minimax_h3/`): `task` = ref2va;
   `duration_seconds` обязателен, 3–15 с (локальный патч сервера); кейфрейм только
   `frame_index: 0`; у reference нет `frame_index`; поля условия — только
   `type/uri/role/frame_index/start_time_seconds`; `aspect_ratio` ∈ {auto, 21:9, 16:9, 4:3, 3:2,
   1:1, 2:3, 3:4, 9:16}; prompt непустой. Тело ответа 4xx sglang не логирует — адаптер сохраняет
   его в задачу.
   Пути — через `normalize_h3_conditions` из `Projects/h3-bench/video_paths.py` (код переносится
   в адаптер, импорта из h3-bench нет).
4. **Таблица форматов.** Холсты панели переводятся в `short_edge` + `aspect_ratio` по явной
   таблице: 896×512 → `512`, `"16:9"` (sglang сам даёт свой кадр; фактический размер берётся из
   mp4, не из запроса); 512×896 → `512`, `"9:16"`; 768×768 → `768`, `"1:1"`. Других холстов при
   sglang нет — отказ на валидации.
5. **Сетка длительностей.** sglang округляет число кадров вверх до сетки `17j+5` при 24 к/с (7 с
   → 175 кадров, `results-beach.jsonl`). Длительности сцен снапятся к этой сетке до постановки в
   очередь; куски трека клипа режутся по **снапнутым** длительностям, чтобы расхождение не
   копилось.
6. `id` сразу пишется в задачу (`job.engine_ref`). Опрос `GET /v1/videos/{id}` каждые 20 с;
   статусы sglang — `queued` / `completed` / `failed`.
7. `completed` → `GET /v1/videos/{id}/content` в `<stem>.mp4`, отчёт `<stem>.json`; затем
   `framecheck`, кейфрейм для следующей сцены, `done`. Сцепленная сцена при сборке теряет кадр 0
   (§3.3.5).

### 4.2. Апскейл (этап `upscale`)

Ставится одной задачей на проект, когда все сцены `done` и этап включён.

1. `acquire ltx` (диспетчер гасит свой H3, поднимает свой ComfyUI).
2. **Одна сила LTX на весь клип:** движение считается по всем частям вместе (логика
   `Projects/h3-bench/motion.py`, переносится в панель), сила выбирается один раз (пороги
   0.6 / 0.3 / 0.15 как сейчас).
3. **Без хостовых скриптов.** Шаблон воркфлоу LTX кладётся в репозиторий
   (`h3_48gb/engines/ltx_workflow.json`, снят с того, что строит
   `Projects/comfy/build_ltx_workflow.py`; при сборке образа проверяется против
   `validate_workflow.py`-правил, перенесённых в тест). Для каждой части: дополнение до `8k+1`
   кадров клоном последнего (ffmpeg в контейнере), загрузка через `POST /upload/image` или путь
   на общем томе, `POST /prompt` с подставленными промптом сцены, силой, `denoise 0.10`, сидом
   42, `GET /history/{prompt_id}` до готовности, результат из `/home/alex/Outputs/comfy/output`
   (том ro) или `GET /view`, обрезка обратно до исходного числа кадров, мукс исходного звука.
   Результат — `<stem>-ltx.mp4` рядом с частью.
4. `assemble` после апскейла собирает финал из `-ltx` частей; черновая сборка из исходных
   остаётся.

### 4.3. Клип под готовый трек

Трек загружается (существующий импорт), длительность ffprobe, сцены по сценарию на сетке
(§3.3.10, §4.1.5), каждая сцена получает свой кусок трека аудио-условием (так H3 в «Танго»
попадал в ритм), при сборке трек мьюксится целиком («песня священна»).

## 6. Тестирование

- Все тесты без MLX проходят **в контейнере**. MLX-тесты помечаются новым маркером `mlx`
  (сейчас есть только `slow`) и в контейнере пропускаются осознанно, со счётчиком пропусков.
- Адаптер, диспетчер и апскейл тестируются против **фейковых серверов** (stdlib HTTP в тестах),
  отвечающих как sglang `/v1/videos*`, ComfyUI `/prompt` `/history` `/view` и `nvidia-smi`.
- **Против пиннинга формы** (главная болезнь репозитория, `CLAUDE.md`):
  - payload сравнивается **точным равенством словаря** для каждого случая §4.1.3, включая
    `aspect_ratio: "auto"`, наличие референсов при кейфрейме, `task: "t2va"` без условий;
  - возобновление: фейк считает `POST` — после рестарта их **ровно один**, опрос шёл по тому же
    `id`; рестарт моделируется **между** `POST` и `completed`;
  - «не гасить чужое»: фейковый kill проверяется на **точный pid** своего процесса, чужой pid ни
    разу не встречается;
  - одна сила LTX: фикстура из частей с **разным** движением, где посценный выбор дал бы разные
    силы, — пачка обязана дать одну;
  - отказ флагов и приём — на argv из настоящего `_scene_generate_args_sglang`;
  - Host/Origin — запрос с LAN-адресом проходит, с чужим — отказ;
  - сетка длительностей: сумма снапнутых длительностей клипа ≥ длительности трека и меньше её +
    одна ячейка сетки.
- Каждый новый тест проверяется мутацией (убрать или обратить защищаемую строку → красный →
  вернуть), ошибка прикладывается к отчёту.
- **Кейфрейм без референсов и t2va на сервере ref2va** — закрыто пробой 07.10, см. §4.1.3.
- **Пробы библиотеки на живом сервере** (нумерация и отсутствие предела уже прочитаны в коде):
  (а) подтвердить генерацией, что `<Picture 1>` — первая reference-картинка при наличии кейфрейма,
  и что `normalize_h3_conditions` не меняет порядок; (б) пик памяти при 3/6/9 картинках.
- Тест сборки промпта: фикстура «два тега, у одного две картинки, плюс кейфрейм» → точное равенство
  итоговых `conditions` и текста `subject_definitions`; мутация порядка картинок роняет тест.
- **Боевые ворота (с владельцем):** проект из **5** сцен по 10 с с двумя референсами — человек по
  фото и окружение (`@...`), —
  сценарий → сцены → апскейл → сборка в панели на alex-neuro (5 — чтобы цепочка прошла больше
  трёх сцепок подряд); отдельно — рестарт контейнера посреди рендера сцены без второго `POST`;
  отдельно — сценарий на Qwen alex-neuro → «выгрузить Qwen» → рендер → «вернуть Qwen».

## 9. Риски и открытое

- **RAM 22 ГБ на хосте.** ffmpeg-сборка длинного клипа рядом с загружающимся H3 может упереться
  в память — сборка ставится, когда диспетчер не поднимает движок.
- **Диск: свободно 125 ГБ.** Образ ~400 МБ; основная нагрузка — видео проектов.
- **Чужой ComfyUI / Qwen Image / Krea2** могут держать карту часами — панель честно ждёт; это
  принято.
- **Обратный конфликт.** Пока движок панели поднят, она держит `generation.lock`; инструменты,
  уважающие замок, подождут. Инструмент, который замок не берёт, запущенный при поднятом H3
  панели, упрётся в нехватку памяти — защита в v1 только плашка «карту держит панель» и кнопка
  «Освободить карту». Полностью закрывает общий менеджер GPU (бэклог h3-bench TODO §5).
- **Прошлые 400 от sglang** разобраны по коду (07.10): `tango-suno-p2` — кейфрейм без
  `duration_seconds`; `beach-01..08` (09-18) — точная причина не установлена (тело ответа не
  сохранялось), текущий payload валиден. Валидатор §4.1.3 закрывает известные причины.
- **Документация h3-bench расходится с кодом sglang по нумерации `<Picture N>`:**
  `docs/h3-shell-howto.md` и `docs/PIPELINE.md` считают кейфрейм `<Picture 1>`, а код его не
  нумерует. Проверить генерацией и исправить документы и скилл Hermes.
- **`server-outputs` sglang** растёт без очистки — вне v1, но диспетчер показывает размер в
  `/status`.

## 10. Интерфейс: две волны и дизайн-трек

  `@`-теги в тексте сцены. Вёрстку старого интерфейса не улучшаем.
