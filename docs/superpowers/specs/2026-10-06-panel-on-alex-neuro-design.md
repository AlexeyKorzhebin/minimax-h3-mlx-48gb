# Монтажная панель на alex-neuro — дизайн

Дата: 2026-10-06. Статус: согласован в диалоге, ждёт чтения владельцем.

## 1. Зачем

Рендер на Маке (MLX) остановлен насовсем 01.10.2026 — слишком долго. Весь рендер идёт на
alex-neuro (CMP 170HX 64 ГБ): MiniMax H3 через sglang, апскейл LTX-2.5 через ComfyUI. Сейчас там
работают только скрипты (`pipeline.sh`, `newscene.py`), всё через ssh. Монтажная панель
(`h3 web` / `h3 worker` этого репозитория: проекты, чат, сценарий, сцены, очередь, сборка)
должна заработать на alex-neuro поверх этих движков и обновляться через Docker.

**Критерий успеха.** Владелец в браузере на Маке открывает `http://192.168.100.50:8765`,
создаёт проект из нескольких сцен, проходит путь «сценарий → сцены H3 → апскейл LTX → сборка» и
получает финальный ролик, ни разу не заходя по ssh.

## 2. Решения, принятые в диалоге

| Вопрос | Решение |
|---|---|
| Продукты v1 | `kind=video` (ролик) и `kind=clip` под **готовый** трек (импорт mp3). Генерация песен (Music3, Whisper) — не в v1 |
| LLM чата/сценария | как сейчас: `providers.json`, любой OpenAI-совместимый адрес (Qwen на alex-neuro :8000, llama-server на Маке, внешний API). Панель LLM не запускает и не гасит |
| Что в Docker | только панель (подход A). H3 и ComfyUI остаются на хосте в своих окружениях |
| Апскейл | пачкой после всех сцен проекта, одна сила LTX на весь клип; включается галочкой |
| Доступ | домашняя сеть, без пароля, порт 8765 на всех интерфейсах хоста. Наружу не пробрасывается |
| Чужое на GPU | панель никогда не гасит чужое (Qwen, ручной ComfyUI, другие лаборатории), уважает `generation.lock`; гасит только то, что подняла сама |
| Код | остаётся в этом репозитории; MLX-движок исключается из образа, но не удаляется |
| Цепочка сцен | через кейфрейм (латентного переноса в sglang нет) |
| Архитектура | сервисы за HTTP, панель — дирижёр; маршрут проекта из включаемых этапов; MCP — v2 |

## 3. Архитектура

```
Мак (браузер) ──http──▶ alex-neuro :8765
   ┌──────────────────── Docker: h3-panel (network_mode: host) ────────────────────┐
   │ web.py + webui           — как есть                                           │
   │ queue / project / assemble / framecheck / runs — как есть                     │
   │ worker.py ── engine "sglang" (новый адаптер) ─────────────▶ H3 sglang :30020   │
   │            └ этап upscale (новый) ────────────────────────▶ ComfyUI LTX :8188  │
   │ provider.py (чат) ───────────────────────────────────────▶ LLM из providers.json│
   └───────────────┬────────────────────────────────────────────────────────────────┘
                   │ http 127.0.0.1:8790
   gpu-dispatcher (хост, systemd): поднимает/гасит H3 и ComfyUI, видит чужие процессы и lock
```

### 3.1. Сервисы

| Сервис | Ответственность | Где живёт | Версия |
|---|---|---|---|
| `panel` | UI, проекты, чат, очередь, маршрут, сборка ffmpeg | Docker | v1 |
| `gpu-dispatcher` | единственный, кто поднимает/гасит движки | хост, systemd | v1 |
| H3 (sglang) | рендер сцены | хост, `Projects/h3-bench/serve.sh` | как есть |
| LTX (ComfyUI) | апскейл | хост, `Projects/comfy` | как есть |
| LLM | чат и сценарий | любой адрес | как есть |
| `mcp` | инструменты для Hermes поверх API панели | Docker | v2 |
| аудио | генерация песни / озвучка | будущий сервис | позже |
| ai-writer | импорт сценария JSON-файлом | внешний | позже |

Не дробим саму панель: веб, очередь, сборка остаются одним процессом. Без брокера сообщений —
очередь файловая (`queue/{pending,running,done,failed}`, `os.rename` + `flock`). Без Kubernetes —
один `docker compose`.

### 3.2. Контейнер `h3-panel`

- База `python:3.12-slim` + ffmpeg. Без CUDA, без `mlx`, `mlx-vlm`. Зависимости панели — из
  нового `requirements-panel.txt` (numpy, pillow, safetensors, jsonschema; без opencv/scipy).
- `network_mode: host` — видит движки и диспетчер на `127.0.0.1`.
- **Пути одинаковые в контейнере и на хосте.** sglang читает условия как `file:///home/alex/...`,
  поэтому том данных монтируется по тому же пути:
  - `/home/alex/Outputs/h3-panel` ↔ `/home/alex/Outputs/h3-panel` (rw) — `H3_OUTDIR`: проекты,
    очередь, загрузки, видео, `providers.json`, `.env`;
  - `/home/alex/Projects/h3-bench/inputs` (ro) — референсы, если нужны.
- Процессы в контейнере: `h3 web --host 0.0.0.0 --port 8765` и `h3 worker`, под одним
  супервизором (простой entrypoint-скрипт: оба процесса, выход контейнера при падении любого,
  `restart: unless-stopped`).
- Пользователь в контейнере — uid/gid `alex` (1000), чтобы файлы на томе принадлежали alex.
- Обновление: `git pull && docker compose build && docker compose up -d`. Данные на томе.

### 3.3. Что меняется в коде панели

1. **Движок как настройка.** `H3_ENGINE=mlx|sglang` (по умолчанию `mlx` — Мак не ломаем).
   `worker.run_job` для `KIND_GENERATE` при `sglang` вызывает адаптер в процессе воркера, а не
   подпроцесс `python -m h3_48gb`.
2. **Адаптер `h3_48gb/engines/sglang.py`.** Принимает тот же `job.args` (argv `h3 generate`),
   разбирает его общим парсером CLI без импорта MLX. Поддерживаемые флаги: prompt, `--width/--height`
   (→ `short_edge` + `aspect_ratio`), `--duration`, `--steps`, `--seed`, `--tag`, `--outdir`,
   `--image` (кейфрейм), `--ref` (новый, повторяемый: референсы персонажей). Остальные флаги
   (`--end-image`, `--latent`, `--save-latent-tail`, `--turbo-*`, `--adaln-cache`, `--checkpoint`,
   `--preview-*`, `--keep-raw`) — отказ с понятной ошибкой `unsupported_on_sglang: <flag>`.
   Артефакты в том же виде: `<stem>.mp4`, `<stem>.json` (отчёт прогона: статус, `wall_s`,
   `inference_time_s`, `peak_memory_mb`, sglang `id`, payload без промпта-дубля). Превью по шагам
   нет — UI это переживает (их и раньше могло не быть).
3. **Dry-run.** `web._dry_run_report` при `sglang` вызывает валидацию адаптера в процессе
   (без подпроцесса и MLX): холст, длительность, известные флаги.
4. **Mac-специфика под условием движка/платформы:** `caffeinate` только на Darwin; кнопка
   «Показать в Finder» скрыта, если сервер не на Darwin; `pkill llama-server` только для
   `llama-local`. `_llm_holds_gpu` при `sglang` не используется — его роль берёт диспетчер.
5. **Маршрут проекта.** В проекте поле `route`: упорядоченный список этапов с флагом
   включения. v1: `scenario`, `scenes`, `upscale` (вкл/выкл, по умолчанию вкл), `track`
   (только импорт готового mp3 для `clip`), `assemble`. Неизвестный этап в `route` — ошибка
   загрузки проекта, а не тихий пропуск.
6. **Персонажи проекта.** В проекте список `characters`: имя, описание, 1–4 фото лица (загрузки
   через существующий `POST /api/uploads`). Каждая сцена передаёт их в H3 как `<Subject N>`
   (`--ref`) по официальному формату Ref2VA (`Projects/h3-bench/skills/h3-prompt-writing/`).
   Генератор сценария получает список персонажей и обязан писать в сцене, кто в кадре.
   **Референсы идут только в сцены, начинающие блок** (первая сцена и сцены с `fresh_start`):
   так работал проверенный клип «Танго» (`Projects/h3-bench/runner_clip2.py`). Сцепленная сцена
   получает только кейфрейм и префикс `i2v_prefix` к промпту; смешивание кейфрейма и
   референсов в одном запросе не проверялось и в v1 не делается.
7. **Новый вид задачи `upscale`** (рядом с `generate`, `song`, `assemble`), см. §4.2.
8. **`h3 web --host`.** Сейчас у `h3 web` есть только `--port` (`cli.py:623`), слушает
   `127.0.0.1`. Добавить `--host` (по умолчанию `127.0.0.1`, в контейнере `0.0.0.0`).

### 3.4. `gpu-dispatcher`

Отдельный скрипт `tools/gpu-dispatcher/dispatcher.py` в этом репозитории (stdlib, ~150–250
строк), ставится на хост как systemd-юнит, слушает `127.0.0.1:8790`. Логика запуска и остановки
переносится из `Projects/h3-bench/pipeline.sh` (`h3_start/h3_stop/comfy_start/comfy_stop`) и
вызывает те же `serve.sh` и ComfyUI-команды.

| Ручка | Поведение |
|---|---|
| `GET /status` | что поднято (H3/ComfyUI, кем — нами или чужое), занятость GPU по процессам, температура, `generation.lock` |
| `POST /acquire {"engine":"h3"\|"ltx"}` | если нужный движок уже поднят — `ready`. Если на GPU чужое или взят `generation.lock` — `wait` с причиной. Иначе гасит **свой** лишний движок, поднимает нужный, отвечает `ready` или `failed` + путь к логу. Долгая операция: ответ `starting`, клиент опрашивает `/status` |
| `POST /release` | гасит свои движки (используется, когда очередь пуста дольше N минут; N=15, настройка) |

«Свой» = поднятый диспетчером (он хранит pid). ComfyUI, поднятый владельцем руками, — чужой: для
апскейла диспетчер может им **пользоваться**, если он уже поднят на :8188, но не гасит его.
Qwen (`qwen38-sglang-dflash2-compose`) — всегда чужой.

## 4. Поток данных

### 4.1. Сцена (этап `scenes`)

1. Воркер берёт `generate`, вызывает `acquire h3`. На `wait` — задача остаётся в `running` со
   статусом «ждём GPU: <причина>», повтор через 30 с; кнопка «отменить» работает.
2. Адаптер собирает `POST /v1/videos` по образцу `Projects/h3-bench/runner_clip2.py`:
   `model`, `prompt`, `task: "ref2va"`, `conditions`, `target`, `num_inference_steps`, `seed`,
   `flow_shift: 12.0`, `audio_flow_shift: 3.0`, `quality: "lossless"`. Условия:
   - сцена начинает блок → референсы персонажей (`role: "reference"`), `aspect_ratio` проекта;
   - сцепленная сцена → кейфрейм `{"type":"image","role":"keyframe","frame_index":0}` (последний
     кадр предыдущей сцены), `aspect_ratio: "auto"`, к промпту префикс `i2v_prefix`;
   - клип → кусок трека этой сцены как `{"type":"audio","role":"reference"}`, длительность
     сцены = длительности куска.
   Пути — через `normalize_h3_conditions` из `Projects/h3-bench/video_paths.py` (перенести в
   адаптер, не импортировать из h3-bench).
3. `id` сразу пишется в задачу (`job.engine_ref`). Опрос `GET /v1/videos/{id}` каждые 20 с,
   прогресс и время — в задачу.
4. Перед отправкой — термозащита: при ≥ 80 °C ждать до 72 °C (статус «остываем, 81 °C»).
5. `completed` → `GET /v1/videos/{id}/content` в `<stem>.mp4`, отчёт `<stem>.json`.
6. Сцепленная сцена повторяет кейфрейм кадром 0 — при сборке он отрезается (в панели это уже
   делает `assemble._drop_head_frames`; проверить, что срез 1 кадр, а не 22 латентных).
7. Дальше без изменений: `framecheck`, кейфрейм для следующей сцены, `done`.

### 4.2. Апскейл (этап `upscale`)

Ставится одной задачей на проект, когда все сцены `done` и этап включён.

1. `acquire ltx` (диспетчер гасит свой H3, поднимает ComfyUI или берёт уже поднятый).
2. **Одна сила LTX на весь клип:** движение считается по всем частям вместе (логика
   `Projects/h3-bench/motion.py`), сила выбирается один раз (пороги как сейчас: 0.6 / 0.3 / 0.15).
3. Каждая часть — через ComfyUI-воркфлоу из `Projects/comfy/run_ltx.sh` (дополнение до 8k+1
   кадров клоном последнего, обрезка обратно, мукс исходного звука), `LTX_DENOISE=0.10`, сид 42,
   промпт сцены. Результат — `<stem>-ltx.mp4` рядом с исходной частью.
4. Задача `assemble` после апскейла собирает финал из `-ltx` частей; черновая сборка из исходных
   частей остаётся доступной.

### 4.3. Клип под готовый трек

Как сейчас в панели для `track.source == "import"`: трек загружается, сцены нарезаются под
длительность, при сборке трек мьюксится («песня священна»). Новое: сцены рендерит sglang, и каждая
сцена получает свой кусок трека аудио-условием (§4.1) — так H3 попадает в ритм и музыку, как в
«Танго». Нарезка кусков — ffmpeg по таймингам сцен, файлы рядом со сценой.

## 5. Ошибки

| Ситуация | Поведение |
|---|---|
| GPU занят чужим / `generation.lock` | задача ждёт, в UI причина; без таймаута; «отменить» снимает |
| движок не поднялся | `failed` + путь к логу движка (`Projects/h3-bench/logs/serve-*.log`, `Projects/comfy/logs/comfy-*.log`) |
| sglang вернул `failed`/`error` | `failed` с текстом ошибки; без авто-повтора; повтор — «пересъёмка» |
| sglang недоступен посреди опроса | 5 попыток с паузой 30 с, затем `failed` «H3 пропал» |
| перезапуск контейнера посреди рендера | воркер при старте видит `running` с `engine_ref`, продолжает опрос того же `id`; если sglang его не знает — `failed` «задача потеряна при рестарте H3» |
| неподдерживаемый флаг | отказ на dry-run, в форме сцены — до постановки в очередь |
| перегрев | пауза с причиной, без отказа |

## 6. Тестирование

- Все тесты без MLX (`test_web`, `test_web_projects`, `test_queue`, `test_worker`,
  `test_project`, `test_assemble`, `test_provider`, `test_chat_web`, `test_runs`,
  `test_framecheck`, …) проходят **в контейнере**. MLX-тесты помечаются маркером и в контейнере
  пропускаются осознанно, со счётчиком пропусков в выводе.
- Адаптер sglang и диспетчер тестируются против **фейковых серверов** (stdlib HTTP в тестах),
  отвечающих как sglang `/v1/videos*` и ComfyUI: формат payload, опрос, `completed/failed`,
  пропажа сервера, возобновление по `engine_ref`, отказ на неподдерживаемые флаги, «чужое на GPU»,
  «не гасить чужое».
- Каждый новый тест проверяется мутацией (убрать или обратить защищаемую строку → красный →
  вернуть), ошибка прикладывается к отчёту — правило `CLAUDE.md`.
- Ловушка ленивости из `CLAUDE.md` здесь не действует (MLX нет), но её аналог есть: фейковый
  sglang отвечает мгновенно, а настоящий — минутами. Тест возобновления обязан моделировать
  рестарт **между** отправкой и `completed`.
- **Боевые ворота (с владельцем):** проект из 3 сцен по 10 с с одним персонажем по фото —
  сценарий → сцены → апскейл → сборка в панели на alex-neuro; плюс отдельный рестарт контейнера
  посреди рендера сцены без потери сцены.

## 7. MCP (v2, интерфейс фиксируется сейчас)

Отдельный контейнер `h3-mcp`, тонкий слой над JSON-API панели (`/api/projects`, `/api/jobs`,
`/api/chat`, `/api/projects/<id>/scenario`, `/api/queue/*`). Инструменты: `list_projects`,
`create_project`, `generate_scenario`, `approve_and_render`, `status`, `upscale`, `assemble`,
`get_result`. v1 не меняет форму этих маршрутов без записи в этом разделе.

## 8. Вне v1

Генерация песни и Whisper на CUDA; MCP; импорт из ai-writer; латентный перенос (Continuum /
Extender); Turbo-LoRA (lightx2v, PDD в sglang) — отдельный A/B после v1; пароль на панель;
упаковка самих движков в Docker (подход B).

## 9. Риски

- **RAM 22 ГБ на хосте.** Панель лёгкая, но ffmpeg-сборка длинного клипа рядом с H3 может
  упереться в память. Сборку ставить только когда GPU-движок не грузится (диспетчер знает).
- **Диск: свободно 125 ГБ.** Образ панели ~300 МБ; основная нагрузка — видео проектов.
- **ComfyUI владельца.** Диспетчер пользуется уже поднятым ComfyUI на :8188, но если в нём
  крутится ручная работа, апскейл встанет в его очередь. Принято: это ожидаемо.
- **Вариант модели.** Только `ref2va`. Если понадобится `fl2va` (кадр конца), это перезапуск
  H3 с другим `VARIANT` — диспетчер поддержит как `acquire h3:fl2va`, но не в v1.
