# Проекты — производство длинного контента. Спека

**Дата:** 2026-08-18. **Статус:** черновик на утверждении. **Ветка:** h3-web (worktree) + main.
**Решения пользователя:** песня первична; главный кейс — длинные видеоролики; кейсы: длинный
ролик / клип на песню / просто mp3; хронометраж — архитектура без ограничения, первый релиз
тестируется на 30–90 с; отдельная страница в вебе; mp3 через чат + тип задачи; гейты после
сценария и после трека, дальше автомат.

## Суть

«Проект» — сущность, производящая длинный контент из кусков на существующей очереди.
Три продукта на одном фундаменте:

1. **Длинный ролик** (главный кейс): сценарий из N сцен → N клипов с автокейфреймами →
   автосклейка. Звук — диегетический звук клипов H3 (как в балладе), опционально песня.
2. **Клип на песню**: сначала песня (этап «трек»), её секции и тайминг задают сцены;
   при сборке аудиодорожка ролика заменяется песней (или микшируется).
3. **Просто mp3**: проект без видео-этапов — сценарий-лирика → трек → готово.

## Хранение

`<outdir>/projects/<YYYYMMDD-HHMM>-<слаг>/project.json` + подпапки этапов.
project.json: kind (video|clip|song), статусы этапов, список сцен (текст промпта, длительность,
статус, job-id, путь клипа), путь трека, границы секций песни, параметры сборки.
Куски считаются обычными задачами существующей очереди в своих папках задач; project.json
ссылается на них по job-id — никакого второго механизма исполнения.

## Этапы и гейты

### 1. Сценарий (чат, гейт)
Диалог в существующей чат-модалке, сессия kind:"project". Qwen разворачивает идею в сценарий:
для ролика — N сцен с длительностями и промптами в формате H3 (связность: общий visual bible —
персонажи/стиль/палитра в system-контексте каждой сцены); для клипа на песню — сначала
лирика+caption, сцены привязываются к секциям песни ПОСЛЕ этапа трека (по реальным границам);
для mp3 — только лирика+caption (+конвертация suno-разметки при импорте готового текста).
JSON-схема ответа расширяется полем project (сцены/лирика). **Гейт: кнопка «Утвердить
сценарий»** — до неё ничего не считается.

### 2. Трек (kind=song, гейт; только clip/song)
Задача очереди kind="song": Music3 (mlx-audio, load_model(Path), ~11–13× реалтайма, пик 24–32 ГБ)
→ wav → мастеринг-проход (ffmpeg: highpass, presence/air EQ, доводка до −13.6 LUFS) → mp3
(оба файла сохраняются). Воркер исполняет song-задачи тем же циклом с тем же GPU-локом
(эксклюзив: H3 и Music3 не сосуществуют). После генерации — Whisper-раскладка по строкам
лирики → границы секций в project.json (для сцен клипа). Длительность: оценка по секциям
(факт: ~28 с/секция для медленных, suno-валидация) с запасом; недопетый хвост ловится
Whisper-проверкой — статус «трек короче лирики, увеличь длительность». **Гейт: прослушать,
«Утвердить трек»** (или пересчитать с другими seed/caption). Для kind=song проект на этом
завершён (mp3 — продукт).

### 3. Клипы (автомат; video/clip)
По утверждённому сценарию (и треку, если clip) сцены уходят в очередь по порядку. Первая сцена —
t2v (или i2v с загруженным кадром). Каждая следующая — i2v от автокейфрейма: кадр из
предпоследней секунды предыдущего клипа (как делали балладу руками). Клип сцены i считается
только после done сцены i-1 (последовательная зависимость через project.json; воркер берёт
следующую сцену, когда предыдущая готова — реализация: submit следующей задачи по завершению
предыдущей, воркер не меняется). Пересчёт отдельной сцены — кнопкой (инвалидирует её и все
последующие автокейфреймы — честное предупреждение). Статусы сцен видны на странице проекта.

### 4. Сборка (автомат)
ffmpeg concat по списку клипов (демиксер concat с перекодировкой в единый профиль).
Для клипа на песню: аудиодорожка = песня (диегетический звук клипов отбрасывается или
микшируется на низкой громкости — параметр проекта, умолчание «только песня»).
Выход: `<проект>/final.mp4` (+ mp3 рядом, если есть трек). Строка в «Закончилось».

## Веб

Отдельная секция «Проекты» на главной странице (список: название, kind, этап, прогресс сцен)
+ страница/панель проекта: этапы с гейт-кнопками, сетка сцен (превью готовых клипов, статусы,
кнопка пересчёта), ссылки на трек/final. Создание проекта — из чат-модалки («Сделать проектом»)
или кнопкой «Новый проект». Дизайн — канон variant-reference (школа Linear), новые элементы
по существующим паттернам.

## Очередь/воркер

Новые kind задач: song (Music3), assemble (ffmpeg, CPU). Клипы — обычные generate-задачи
с пометкой project/scene в note. GPU-лок общий (существующий лизинг). Оценка длительности
проекта = сумма оценок кусков; показывается на странице проекта.

## Первый релиз (ворота)

Тест: (а) mp3-проект целиком (лирика в чате → трек с мастерингом → mp3); (б) видеоролик
30–90 с из 3–5 сцен на малом канвасе — сценарий в чате → гейт → автоклипы → автосклейка,
связность персонажа между сценами глазами; (в) клип на песню 30–60 с (обрезанная песня или
короткая песня) — сцены по секциям, сборка с заменой аудио. Хронометраж >90 с архитектурно
не ограничен, но не тестируется в первом релизе.

## Вне рамок

- Face-refine (запаркован), внешние стоки, миграция старых чат-сессий.
- Умный монтаж (переходы кроме прямой склейки/`<scenetrans>` внутри сцен).
- Параллельный счёт кусков (GPU один — куски последовательны by design).
- Редактор таймлайна: сцены редактируются как текст в чате, не drag&drop.

## Риски

- Связность персонажей между сценами: автокейфрейм несёт композицию, но не гарантирует
  идентичность вне кадра — лечится visual bible в промптах сцен; проверяется воротами (б).
- Music3-хвост: недопетая лирика — Whisper-гейт со статусом.
- Длинные проекты (3 мин = 18-20 клипов): часы GPU; статусы и возобновляемость через
  project.json обязаны переживать рестарт сервера/воркера.
- Эмоциональность песен: ручка — caption (эксперимент v2-emotion в работе); в чат-промпт
  Qwen добавить требование «актёрской задачи» в caption.

## Дополнение 2026-08-18: импортированный трек (решение пользователя)

Источник трека clip-проекта: `generate` (Music3) ИЛИ `import` (готовый mp3 — например,
из suno — плюс его лирика). Мотив: потолок вокальной актёрки Music3 зафиксирован тестом
«Колыбельной»; драматические песни поются во внешнем сервисе, наш конвейер даёт видеоряд.

Механика import: mp3 загружается аплоадом, лирика — текстом (suno-разметка конвертируется
как в чате); этап «трек» не генерирует и не мастерит — только Whisper-раскладка секций по
времени (та же, что для своих треков) и гейт прослушивания/утверждения. Дальше конвейер
не различает источники. В project.json: track.source: "generate" | "import".
