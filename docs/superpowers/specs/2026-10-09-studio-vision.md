# Студия генерации: видение (2026-10-09)

Статус: **видение на ревью**, это ещё не спека. Документ собран из разговора с владельцем 09.10.
На его основе пишутся спеки частей (§7).

## 1. Зачем

Владельцу нужно **как можно быстрее делать контент**: ролики, клипы, картинки. Инфраструктура
сама по себе не цель. Сейчас есть монтажная панель (волны 1–1.5) под одну модель, MiniMax H3 на
sglang. Проход владельца 08.10 показал, что сам он путь не проходит: сцены теряются, режим молча
один, всё на английском. Пробы 08–09.10 показали, что у одной модели несколько режимов со своими
лимитами (`docs/h3-modes/`).

Рядом уже стоят другие генераторы, и их будет больше:
- картинки: Krea 2 (Raw для LoRA, Turbo на 8 шагов), Z-Image Turbo (с обучением LoRA);
- видео: H3 в вариантах `fl2va`/`ref2va`; Wan и другие — позже;
- апскейл: LTX / SeedVR2;
- музыка: YuE2.

Типичная задача сочетает несколько моделей. Например: эскиз первого кадра на Krea 2 с LoRA героини,
анимация в H3 «от кадра», продолжения цепочкой, апскейл, сборка.

## 2. Принцип: мы — режиссёр, ComfyUI и sglang — исполнители

Своего движка графов, загрузчика моделей и LoRA **не пишем**. Это делает ComfyUI, и новые модели
появляются в нём в первые дни (Krea 2 работает там «из коробки»).

**Наш продукт** — слой, которого у ComfyUI нет:
- проект → сценарий → сцены → эскизы → финал → сборка;
- герои и референсы с ролями;
- LLM-сценарист и Vision-критик;
- очередь проекта поверх одной или нескольких машин и одной видеокарты;
- интерфейс самообслуживания (телефон 390 px обязателен).

**Исполнители:**
- **ComfyUI** — картинки, апскейл, со временем большая часть видео. Один адаптер: workflow
  хранится в формате API как шаблон, адаптер подставляет промпт, сид, LoRA и входные ресурсы, ставит
  задачу и читает прогресс по веб-сокету. Новая модель = новый шаблон, а не новый код.
- **sglang H3** — остаётся, пока ComfyUI-узлы H3 не сравнены на железе. Работает, замерен, держится
  на трёх локальных правках.
- **LLM / Vision провайдеры** — CAILA (платно), локальная модель на Маке (бесплатно), любой
  OpenAI-совместимый адрес.

## 3. Ядро

- **Узлы.** Каждый исполнитель — узел с адресом в настройках. Возможности узла описаны карточкой:
  режимы, лимиты, форматы кадра, длительности, LoRA, формат промпта, стоимость, цена перезапуска.
  Интерфейс и проверка ввода строятся из карточки. Пример строк карточки: «не больше 6 картинок»,
  «портретный кадр в ref2va нельзя». Ядро следит, жив ли узел. Узлы могут быть на разных машинах.
- **Ресурсы с происхождением.** Картинка, ролик, кадр, трек, LoRA — ресурсы библиотеки. Любой
  ресурс можно подать на вход другому шагу; у каждого записано, из чего он получен.
- **Шаги и цепочки.** Шаг — вызов одного узла (workflow ComfyUI, задача sglang, вызов LLM).
  Цепочка — короткий список шагов уровня продукта («кадр → анимация → критик → апскейл»), который
  хранится в базе как граф задач. Падение шага перезапускает шаг, а не цепочку. Сложная графовая
  логика живёт внутри workflow ComfyUI. **Редактора графов у нас нет.**
- **Очередь** группирует задачи по узлу и варианту: смена модели на одной видеокарте 64 ГБ стоит
  минуты. Работает через существующий диспетчер GPU.
- **Монолит ядра + исполнители-сервисы.** Ядро — один сервис: проекты, ресурсы, очередь,
  маршрутизация, LLM-роли. Исполнители — отдельные процессы или контейнеры со своими зависимостями.
  Брокера сообщений нет: один пользователь, узкое место — VRAM, а не транспорт.

## 4. LLM-роли и критик

- **Роли.** «Сценарист» (сцены, промпты по шаблону движка) и «Критик» (Vision: оценивает результат).
  Каждая роль привязана к своему провайдеру, и провайдеры могут жить на разных машинах. Сейчас обе
  роли может закрывать одна модель, но в коде они разделены с первого дня.
- **Шаблон промпта по движку.** Сцена пишется один раз, по смыслу: действие, эмоция и игра, звук
  через походку и материал. Под H3 `fl2va`, H3 `ref2va`, Krea 2 или Z-Image её собирает свой шаблон.
- **Цикл критика.**
  1. Результат готов; ядро отдаёт кадры (или видео, если провайдер умеет) и критерии. Критерии
     берутся из сцены и из общих принципов владельца: «не зомби-лицо», «руки живые».
  2. Критик возвращает вердикт, причины и правку промпта.
  3. Политика решает: только показать, переснять с другим сидом или переписать промпт и переснять.
     Есть потолок попыток и бюджет минут GPU.

  По умолчанию критик **только советует**. Автоповтор включается на проект. Цена ошибки: эскиз
  стоит 4–6 мин GPU.

## 5. Интерфейс: мастер, чат-проводник или оба

Уже согласовано (CJM `2026-10-09-panel-wave2-CJM.md`, макет `variant-a-wave2`):
- мастер Идея → Кастинг → Сценарий → Эскизы → Финал → Сборка;
- проекты как главный экран;
- раздел «Готовое» (галерея финалов);
- быстрая проба: одна сцена, по готовности превращается в проект;
- темы: Apple-светлая, тёмная, как в системе.

**Открытый вопрос.** Владелец хочет как можно быстрее делать контент. Возможно, основной путь —
**чат-проводник**: модель ведёт диалогом и вставляет в ленту готовые виджеты (формат кадра, загрузка
референса, карточки сцен, плеер эскиза). Справа при этом виден живой проект, и в любой момент можно
перейти в мастер.

Предварительная ставка — гибрид. API строится как набор явных операций («создать проект», «добавить
сцену», «задать режим», «поставить эскиз»), удобных и для чата как инструменты, и для MCP Hermes.
Виджеты — те же компоненты, что в мастере. Что делать первым, мастер или чат, — вопрос ревью.

### 5а. Дополнение владельца: чат-проводник через Hermes и MCP Apps

Владелец предлагает делать диалоговый режим через готового агента, а не писать свой чат. Это
**не обязательно Hermes**: подойдёт OpenClaw, Claude Desktop или любой другой популярный агентный
движок. Отсюда требование: студия не привязывается к одному хосту. Её интерфейс для агентов —
стандартный MCP-сервер (+ MCP Apps), и любой хост с поддержкой MCP становится чат-проводником.
Hermes — первый кандидат, потому что он уже стоит и настроен.

**Что уже есть у Hermes** (v0.21.5 на Маке):
- чат в терминале, десктоп-приложении и Telegram;
- память, скиллы (уже есть `h3-video`), kanban и cron;
- доска `image-studio`: Z-Image через Draw Things на Маке, локальная LLM и шаг review.

**Что тогда делаем мы:**
- **MCP-сервер студии.** Операции ядра становятся инструментами: «создать проект», «добавить сцену»,
  «поставить эскиз», «показать готовое».
- **Веб-интерфейс** остаётся для мастера, галереи «Готовое» и настроек узлов.

**MCP Apps** (SEP-1865, официальное расширение MCP, спека 2026-01-26):
- как работает: инструмент объявляет ресурс `ui://` с HTML, хост рисует его в песочнице-iframe
  прямо в диалоге, виджет общается с хостом по JSON-RPC (вызов инструментов, follow-up сообщение);
- поддерживают: Claude, ChatGPT, VS Code, Goose;
- Hermes: **поддержки в коде v0.21.5 не нашёл** (нет обработки `ui://`). Telegram iframe не рисует
  вообще.

**Ставка:** каждый инструмент отдаёт и текст со структурой и медиа (работает везде, включая
Telegram), и `ui://`-виджет (богато там, где хост умеет). Виджеты собираются из тех же компонентов,
что веб-интерфейс.

**Открыто:**
- добавит ли Hermes поддержку MCP Apps, или свой рендер делаем через слоты плагинов десктопа
  (`web/src/plugins/slots.ts`);
- доступность медиа (ролики с `:8765`) из песочницы хоста.

## 6. Ограничения

- alex-neuro недоступна до ~19.10 (электричество). До возврата: только код и тесты на
  имитациях узлов. Имитации отдают реальные ролики проб 08–09.10 с правдоподобными таймингами.
  ComfyUI можно поднять на Маке (MPS) с маленькой моделью, чтобы проверить API-договор.
- Одна видеокарта CMP 170HX 64 ГБ. ComfyUI на ней уже работает (LTX, `:8188`); не проверен H3 внутри ComfyUI (поправка ревью, `vision-review/SUMMARY.md`).
- Правила проекта: тест виден красным; план проверяет не автор; логи не в /tmp; нельзя генерировать
  обнажённых реальных людей и любых несовершеннолетних.
