**1. Hermes вместо собственного чата**

За: уже доступны диалог, Telegram, скиллы и восстановление сессий. Студия получает второй способ управления через те же операции API, без разработки истории сообщений, стриминга и выбора моделей.

Против: Hermes не снимает неоднозначность команд, повторы вызовов и риск устаревшего контекста. «Пересними вторую сцену» должно разрешаться в конкретные `project_id`, `scene_id`, ревизию и параметры. Длительная генерация должна жить в worker студии, переживая закрытие Hermes.

MCP-инструмент постановки возвращает `job_id`; состояние читается отдельным инструментом. Повтор запроса с тем же ключом идемпотентности возвращает прежнюю задачу. Перед затратным запуском — явные параметры и подтверждение.

**Проверка Hermes:** по всему установленному дереву не нашла `ui://`, `io.modelcontextprotocol/ui`, `text/html;profile=mcp-app`, `AppBridge` или обработки `resourceUri`. Оснований считать его MCP Apps-хостом нет.

`web/src/plugins/slots.ts` предоставляет позиции `chat:top/bottom`, но не рендерер виджетов отдельных сообщений. Electron использует собственный механизм contributions/runtime plugins, независимо от веб-панели. В `apps/desktop/src/contrib/runtime-loader.ts` прямо указано: плагин исполняется с полномочиями приложения; это **не песочница**. Панель студии сделать можно; поддержка MCP Apps потребует отдельного протокольного моста и изоляции.

Мастер исправляет уже наблюдавшиеся потери сцен и скрытые режимы. Наличие Hermes уменьшает объём работы, но не доказывает удобство диалогового пути.

**3. Реальны ли MCP Apps сейчас**

Да: стандарт и готовые хосты существуют. Для локальной пробы выбрала бы **Goose либо VS Code**, для отладки — официальный `basic-host`. Поддержка Claude, ChatGPT, Goose и VS Code подтверждается [проектом MCP](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/).

`ui://` доставляет HTML через MCP; оно **не обеспечивает доступ к роликам**. `alex-neuro` как SSH-алиас не обязан разрешаться браузером. Если медиа доступны по HTTP, возникают ограничения HTTPS-хоста, CSP и частной сети; для `fetch` дополнительно CORS. CSP должен разрешать медиа через `resourceDomains`, запросы — через `connectDomains`; разрешение принимает хост. [Спецификация](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx).

Практичный вариант — HTTPS-прокси медиа студии с авторизацией, короткоживущими ссылками и HTTP Range для видео. Проверять нужно из конкретного iframe.

Телефон: Claude официально поддерживает интерактивные connectors на iOS/Android, но нужен доступный удалённому хосту MCP endpoint. [Документация](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude). Telegram — текст, медиа и ссылка на мастер; iframe туда не переносится.

**4. Единственный источник состояния**

База студии владеет проектами, сценами, дублями, очередью, бюджетами и происхождением. Hermes хранит разговор и предпочтения; проектные сведения в памяти — лишь подсказки для повторного чтения API.

Все изменения проходят через студию с `expected_revision`; конфликт требует перечитать состояние. Kanban и `image-studio` могут показывать ссылки и проекции задач, но не вести вторую очередь генерации. Существующие изображения импортируются как ресурсы с происхождением, без двусторонней синхронизации хранилищ.
