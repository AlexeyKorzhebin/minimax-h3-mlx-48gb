## 1. Цель и критерий готовности

**Цель.** Панель, с которой владелец работает без помощи: новый интерфейс по макету A («мастер»:
Проекты / Референсы / Очередь / Настройки, проект — страница с адресом и шагами маршрута), под ним —
сервер, где роутинг, проверка тел и контракт ошибок не пишутся руками, состояние в SQLite,
обновления приходят событиями, а не опросом. Попутно — MCP для Hermes и общий с ai-writer слой
LLM-провайдеров (если владелец выберет общий, §2в).

**Критерий готовности (один, как в 1.5).** Владелец сам, в браузере на Маке, без ssh, curl и правки
файлов, проходит в **новом** интерфейсе сценарий приёмки. Тот же сценарий закреплён e2e-тестом
Playwright на собранном клиенте, настоящем сервере и фейковых движках, и тест зелёный в CI-прогоне
образа.

Сценарий приёмки (проект; уточнить с владельцем, §4):
1. Референсы: загрузить картинку → карточка `@тег` → новая версия → видно «где используется».
2. «+ Новый проект» → вид «Ролик» → сценарий: (а) из чата внутри проекта, «Применить к проекту»;
   (б) без LLM: 2–3 сцены по 3–5 с в редакторе сцен, `@`-подсказка, стартовый кадр сцены 0, сид.
3. «Утвердить» → сцены идут; прогресс и причина ожидания карты видны **без перезагрузки** (SSE),
   плашка GPU на любом экране.
4. «Пересчитать сцену» с правкой промпта и сида, видно каскад «пересчитает #1, #2».
5. Апскейл LTX (галочка) → отчёт «сила 0,6 · 3 из 3 частей» → сборка → «Скачать».
6. То же на 390 px без горизонтальной прокрутки (если владелец подтвердит, что смотрит с телефона).

e2e-версия сценария — фейковые sglang/ComfyUI/диспетчер (они уже есть в тестах волны 1), короткие
сцены, без реального GPU. Живой проход владельца — отдельно и обязательно: e2e проверяет, что
путь есть, а не что им удобно пользоваться.

### (а) API на FastAPI + Pydantic, контракт = текущие HTTP-тесты

**Входит.** Перенос всех `/api/*` и `/media/*` группами (библиотека, проекты, сцены, очередь, чат,
провайдеры, GPU) на FastAPI; модели запросов и ответов; единый обработчик ошибок с тем же телом
`{error: {code, message, detail}}` и той же картой кодов в статусы (`cli.ERROR_CODES`, карта статусов в
`web.py`); проверка Host/Origin (защита от DNS rebinding, сейчас `_respond` в `web.py` до любого
маршрута) — middleware; раздача медиа с Range; OpenAPI как артефакт сборки. Бизнес-логику из
`web.py` (разбор хода чата в сцены, сетка длительностей, `_scenario_context` и т. п.) вынести в
модули-сервисы, чтобы маршруты стали тонкими.

**Факты о сетке тестов (замер 2026-10-08, ветка `feat/panel-ui-gaps`).** STACK пишет «около 1900
HTTP-тестов» — это завышено. Всего `def test_` — 2009 в 84 файлах; в 28 файлах, поднимающих сервер
через `_serve`, — 997 тестов; реально делают HTTP-запрос по грубой эвристике около 400. Тесты ходят
по настоящему HTTP (`tests/test_web.py:1675`, `_call` через `http.client`), это хорошо: подменив
`_serve` на запуск uvicorn, большую часть можно гонять без правки. Но около 30
`monkeypatch.setattr(web…)` и около 40 прямых вызовов `web._…` привязаны к внутренностям `web.py` —
их придётся перевести на новые модули.

**Риски.**
1. **Порядок проверок.** FastAPI проверяет тело *до* обработчика и отвечает 422 со своим форматом.
   Текущий контракт — 400 `args_invalid` нашим текстом, а 404/409 (`project_running`) проверяются
   **до** чтения тела (спека 1.5 §5.5). Наивный перенос сломает именно класс находок «400 вместо
   404», ради которого стек меняется. Решение: свой обработчик `RequestValidationError` в наш формат
   и зависимости «проект существует / не занят» раньше разбора тела; тесты порядка — первыми.
2. **Тексты отказов закреплены точным равенством** — Pydantic-сообщения не годятся, нужны наши.
3. **Объём.** `web.py` — 6762 строки, и это не только роутинг. Оценка STACK «несколько дней»
   выглядит оптимистичной (гипотеза; проверить инвентарём маршрутов и сервисной логики в спеке (а)).

**Зависимости:** нет. Первый по порядку. **Оценка:** M–L, 6–10 дней.

### (б) SQLite-хранилище + миграция файлов

**Входит.** Один файл БД в outdir, WAL, `busy_timeout`; таблицы проектов, сцен, карточек и версий,
связей «проект/сцена → карточка» (внешний ключ вместо ручного скана при удалении карточки),
чат-сессий, истории оценок. Медиа на диске, в БД пути. Скрипт импорта `project.json`, каталогов
библиотеки, сессий чата; сверка «до/после» на копии боевого outdir. Бэкап — копия файла по расписанию.

**Риски.**
1. STACK говорит, что `project.py`, `assemble.py`, `worker.py`, `library.py` «переносятся как есть».
   Это верно для (а), но не для (б): они сами читают и пишут `project.json` и каталоги карточек под
   `flock`. (б) меняет их слой хранения — нужен адаптер хранилища, за которым они не замечают смены.
2. Два контейнера пишут в один файл. На локальном диске хоста WAL работает; на SMB/NFS — нет.
   Путь `/home/alex/Outputs/h3-panel` локален, но доступ с Мака идёт по SMB (бой, §5.1) —
   открывать БД с Мака нельзя, только через API.
3. **Рекомендация против «месяц держать запасное чтение из файлов»** (STACK §3): двойное чтение —
   новый источник расхождений. Предлагаю разовый импорт + файлы как архив только для чтения + откат
   = вернуть прежний образ. Решает владелец.

**Зависимости:** после (а) (сервисный слой уже выделен). **Оценка:** M, 4–6 дней.

### (в) Общий слой LLM-провайдеров с ai-writer 2.0

**Что есть.** У панели `provider.py` (971 строка): синхронный urllib, `providers.json` + `.env`,
строгая `json_schema`, SSE против обрыва шлюза. У ai-writer `integrations/llm/` (~3200 строк):
async OpenAI SDK, профили моделей в БД с ключами под Fernet, ретраи, continuation, проба
возможностей, ARQ + Redis; строгую схему он не шлёт. По отчёту сравнения общего в коде —
четыре чистые функции (семейство модели → ключ лимита и temperature, классификация моделей,
content-блоки Anthropic, вырезание обёрток); по возможностям наш клиент сильнее на structured output.
Выбор модели (спека 1.6) не реализован: `list_models`/`wire_defaults` в коде нет.

### (г) SSE-события

**Входит.** `GET /api/events` (SSE): прогресс задачи, смена статуса сцены и этапа проекта, очередь
(взята / пауза / автопауза после опустения), плашка GPU (опрос `/status` диспетчера на сервере, а
не в браузере), уведомления. Клиент держит одно соединение, `/api/state` остаётся для MCP и отладки.

**Ключевой вопрос — источник событий.** Worker в отдельном контейнере, web о его делах не знает.
Предложение: один журнал событий, в который пишут web и worker (сейчас JSONL рядом с
`events.jsonl` диспетчера, после (б) — таблица), SSE его «хвостит». Тот же журнал читают отчёт
боя (`tools/battle_report.py`, STACK §5 «Логи»), внешние уведомления (TODO §5) и MCP. Это закрывает
и находку боя «автопауза не пишется в журнал» (бой §5.2).

**Риски:** переподключение и пропуск событий (нужен `Last-Event-ID` или «после переподключения —
снимок + хвост»); прокси и буферизация (у нас LAN без прокси — низкий).
**Зависимости:** после (а); до (д), чтобы клиент сразу строился на событиях. **Оценка:** S–M, 2–3 дня.

### (д) Новый клиент: React + Vite + TypeScript по макету A

**Входит.** Разделы Проекты / Референсы / Очередь / Настройки; проект — страница с адресом
`#/projects/<id>/<шаг>`, степпер маршрута по виду проекта (IA §3); плашка GPU везде; редактор сцены
с `@`-подсказкой и полоской картинок; пересъёмка с каскадом; встроенные подтверждения и «отмена
5 с» вместо `window.confirm` (долг 1.5); чат как боковая панель проекта; 390 px. Типы из OpenAPI
(`openapi-typescript`), состояние сервера — через один кэш запросов + SSE-инвалидация, без ручной
синхронизации (`draftEpoch`, `syncDraftFromDom`). Сборка — multi-stage в образе.

**Правило переноса.** Сейчас ряд правил живёт дважды — в Python и в `app.js` (сетка длительностей,
каскад пересъёмки, тексты блокировок; спека 1.5 §7 сверяет их тестом). Предложение: в волне 2
считать такие вещи на сервере (поле в ответе или маршрут предпросмотра) и не переписывать их на TS.

**Риски.** Самый крупный подпроект; объём зависит от добивки макета (см. «Предварительно»).
Переходный период — две вёрстки одновременно (§4). **Зависимости:** (а), (г); удобнее после (б), но
не обязательно, если API не меняется. **Оценка:** L, 10–15 дней.

### (е) MCP для Hermes поверх OpenAPI

**Входит.** Контейнер `h3-mcp` (спека W1 §3.1, §7), транспорт HTTP в LAN, Hermes на Маке. Набор
инструментов **ручной и короткий**, а не автогенерация из всех ~45 веток роутинга `web.py`: `list_projects`,
`create_project`, `generate_scenario`, `approve_and_render`, `status`, `upscale`, `assemble`,
`get_result` (W1 §7) + `gpu_status`, `release_gpu`. OpenAPI — источник типов и описаний, не набор
инструментов. Ответ «ждёт карту: <кто>» — обычный результат, не ошибка.

**Риски.** У панели нет пароля (W1, решение «домашняя сеть»); MCP даёт агенту право ставить задачи
на GPU — нужны подтверждения на дорогих действиях или белый список. Описание инструментов —
единственное, что видит Hermes: тексты нужно проверять прогоном Hermes, а не чтением.
**Зависимости:** (а). Не зависит от (д) — может идти раньше UI, если владелец захочет. **Оценка:** S–M, 2–4 дня.

### (ж) e2e на Playwright

**Входит.** Стенд: образ панели + фейковые sglang / ComfyUI / диспетчер (есть в тестах W1) + чистый
outdir; Playwright на собранном клиенте. Сценарий приёмки §1 — первый тест. Заменяет node-харнесс
с фейковым DOM (`tests/_ui_harness.mjs` и около 380 тестов в файлах, где есть `_node_eval`).
Мутационная проверка — как везде (CLAUDE.md): каждый e2e-шаг увиден красным.

**Риски.** Хрупкие селекторы — договориться о `data-testid`/ролях с первого экрана; время прогона
с фейковыми движками должно быть минутами. **Зависимости:** каркас стенда — вместе с (а) (API-уровень
сценария, страховка порта), браузерные шаги растут с (д). **Оценка:** M, 3–5 дней, размазано.

### (з) Очередь таблицей в SQLite

**Входит.** Перенос `queue/{pending,running,done,failed}` в таблицу той же БД; постановка задачи и
изменение проекта одной транзакцией (закрывает класс «сцену поставили, проект не обновился», C2
финального ревью W1); `reconcile` после рестарта с `engine_ref` (W1 §5) на новом хранении;
автопауза как запись в журнал событий. Диспетчер GPU не трогается.

**Риски.** Очередь — самое проверенное место (рестарт посреди рендера без второго `POST`,
не гасить чужое); перенос должен пройти те же тесты точным равенством. Видимость через `ls`
теряется — нужна команда/страница. **Зависимости:** после (б). **Оценка:** M, 3–5 дней.
