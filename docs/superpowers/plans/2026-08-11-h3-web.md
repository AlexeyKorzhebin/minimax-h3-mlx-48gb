## Глобальные ограничения

Нарушение — основание отклонить задачу на ревью.

- **Ни одной новой зависимости.** Только стандартная библиотека.
- **`h3_48gb/web.py`, `h3_48gb/queue.py`, `h3_48gb/worker.py` не импортируют `mlx`** — ни при
  импорте модуля, ни при обработке запроса. MLX живёт только в подпроцессе.
- **Сервер слушает только `127.0.0.1`.**
- **Каждая запись, о которой кому-то сообщили «готово», — durable:** временный файл →
  `fsync(файл)` → `os.replace` → `fsync(каталог)`. Это относится к файлам задач, снимкам промптов,
  отметкам результата и к `PUT /api/prompts`. Образец — `CheckpointStore.write`
  (`h3_48gb/checkpoint.py:368`).
- **`caffeinate -dimsu` оборачивает задачу, а не работника.**
- **Все коды ошибок — в `ERROR_CODES` (`h3_48gb/cli.py`)**, ни одного кода рядом. **Код добавляет
  та задача, которая его бросает**, а не задача 3 оптом: в `tests/test_cli.py` есть
  `test_error_codes_are_documented_in_one_place`, требующий двустороннего соответствия — каждый
  код словаря обязан иметь настоящий `raise`. Запись без `raise` — ложь в контракте, а список
  исключений превратил бы двустороннюю проверку в одностороннюю ровно на то время, пока в
  словарь и лезут новые записи. Раскладка: `worker_already_running` — задача 4;
  `path_outside_root`, `prompt_name_invalid`, `queue_unwritable` — задача 5;
  `args_invalid`, `command_not_allowed`, `output_stem_conflict`, `job_not_pending` — задача 6.
- **Комментарии и docstring по-английски**, текст интерфейса и сообщения пользователю — по-русски.
- **Мутационная проверка обязательна** для каждого теста, покрывающего замки, переходы состояний,
  сверку и проверку путей: удалить или инвертировать защищаемую строку, увидеть красноту, вернуть.

- **Тест, который не покраснел на мутации, считается несуществующим.** Если он не краснеет —

**Три решения, которые нельзя переиначить:**

`output_stem` берётся **только** из `dry_run_report["output_stem"]` — отчёта, который напечатал
сам CLI. Произвольную строку от вызывающего кода очередь не принимает: канвас при `--image`
выводится кодом, который тянет MLX, поэтому единственный, кто знает настоящее выходное имя, — это
`generate --dry-run`.

**Снимок промпта делает `submit`, а не вызывающий.** Путь снимка содержит `id`, а `id` появляется
внутри `submit`. Порядок: создать файл задачи по `O_CREAT|O_EXCL` (так `id` становится занят) →
записать снимок durable → подменить в `args` значение `--prompt-file` на путь снимка → записать
файл задачи целиком. Если `prompt_text` не передан, снимка нет и `args` не трогаются.

**Столкновение выходного имени** проверяется по `pending/`, `running/` и по существованию на диске
**любого** из `ARTIFACT_SUFFIXES`, не только `.mp4`: оставшийся `.wav` или `.json` — тоже занятое
имя, и его тоже затрут.

```python
def test_durable_write_survives_a_crash_after_the_temp_file(tmp_path, monkeypatch):
    """Not "no temp file is left" — that passes with a plain write_text. The invariant is that
    a crash mid-write leaves the OLD content, never a mixture."""
    target = tmp_path / "job.json"
    q.write_json_durably(target, {"v": 1})

    real_replace = os.replace
    def boom(src, dst):
        raise OSError("simulated crash between fsync and rename")
    monkeypatch.setattr(q.os, "replace", boom)
    with pytest.raises(OSError):
        q.write_json_durably(target, {"v": 2})
    monkeypatch.setattr(q.os, "replace", real_replace)

    assert json.loads(target.read_text()) == {"v": 1}, "a failed write corrupted the old content"
    assert list(tmp_path.iterdir()) == [target], "the temporary file was not cleaned up"


def test_durable_write_fsyncs_the_file_and_its_directory(tmp_path, monkeypatch):
    """Without the directory fsync the rename itself can be lost, and a job the user was told
    is queued is simply gone after a power cut."""
    synced: list[bool] = []
    real_fsync = os.fsync
    monkeypatch.setattr(q.os, "fsync", lambda fd: (synced.append(os.fstat(fd).st_mode), real_fsync(fd))[1])
    q.write_json_durably(tmp_path / "j.json", {"v": 1})
    assert len(synced) == 2, f"expected fsync of the file and of the directory, got {len(synced)}"
```

```python
@contextlib.contextmanager
def _external_lock(root, mode):
    """Hold the queue lock from a *separate process*: flock is per-process, so a thread in this
    one would silently re-acquire its own lock and prove nothing."""
    script = ("import fcntl, os, sys, time\n"
              "fd = os.open(sys.argv[1], os.O_RDWR | os.O_CREAT)\n"
              f"fcntl.flock(fd, fcntl.{mode})\n"
              "print('held', flush=True)\n"
              "sys.stdin.readline()\n")
    proc = subprocess.Popen([sys.executable, "-c", script, str(Path(root) / "queue.lock")],
                            stdin=subprocess.PIPE, stdout=subprocess.PIPE, text=True)
    assert proc.stdout.readline().strip() == "held"
    try:
        yield
    finally:
        proc.stdin.write("\n"); proc.stdin.flush(); proc.wait(timeout=5)


def test_the_queue_lock_actually_blocks_a_second_exclusive_holder(tmp_path):
    root = tmp_path / "queue"; q.layout(root)
    with _external_lock(root, "LOCK_EX"):
        done = threading.Event()
        threading.Thread(target=lambda: (q.queue_lock(root, exclusive=True).__enter__(),
                                         done.set()), daemon=True).start()
        assert not done.wait(0.5), "queue_lock returned while another process held it exclusively"
```

**Потребляет:** всё из задачи 1. **Производит:**

```python
def claim(root, now=None) -> Job | None          # pending/ → running/, записывает started_at
def finish(root, job_id, exit_code, log_tail, finished_at=None) -> Job
def update(root, job_id, args, note, dry_run_report, estimate,
           prompt_source=None, prompt_text=None) -> Job
def move_to_front(root, job_id) -> Job
def cancel(root, job_id) -> Job
```

**`started_at` пишет `claim`, и только он.** Работник его не трогает — так велит спека, и так
проще: аренду работник берёт после захвата, и порядок «сначала запись времени, потом аренда»
получается сам собой.

`finish` принимает `finished_at`, потому что сверка при старте (задача 4) восстанавливает время из
отметки результата, а не выдумывает его заново.

`update` проверяет столкновение `output_stem` теми же правилами, что `submit`, исключая саму
правимую задачу. Снимок промпта перезаписывается durable-протоколом; `id`, `created_at` и
`priority` сохраняются.

```python
            observed["marker_during_wait"] = q.result_path(root, job.id).exists()
```

```python

```

Маршруты: `POST /api/jobs`, `PUT /api/jobs/<id>`, `POST /api/jobs/<id>/top`,

`estimate` → `queue.submit(..., prompt_text=<текст промпта>)`. **Снимок делает очередь**, сервер
только передаёт текст.

Формула оценки — из спеки:

```
rows      = (5.53 + 1.641*(sec - 2.4)) * (W/16) * (H/16) + 81*sec + 820
s_forward = 5.699e-3*rows + 2.671e-7*rows**2
overhead  = 36 + 7.44e-5 * W * H * sec
seconds   = s_forward * (steps - 1) + overhead
peak_gb   = 9.3*rows/37657 + (22.1 if bits == 8 else 12.1)
```

`bits` — из `quant_config.json` каталога чекпойнта; файла нет — 4.
