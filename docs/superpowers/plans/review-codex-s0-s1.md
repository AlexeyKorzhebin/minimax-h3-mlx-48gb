**Блокер**

1. **Текст ошибки провайдера может вынести секрет в ответ API и отчёт.**  
   **Где:** задача 8, П:3352–3354; задача 13, П:5691; [provider.py:933](</Users/aleksey.korzhebin/Yandex.Disk.localized/Projects/minimax-h3-mlx-48gb/h3_48gb/provider.py:933>).  
   `ProviderLlm` вставляет `str(err)` в публичное сообщение. Ветка `bad_model_json` существующего провайдера включает первые 400 символов ответа без редактирования секретов. Воспроизведено с искусственным ответом: `модель не удержала формат: Bearer SYNTHETIC_SECRET_FOR_REVIEW`. План затем предписывает переносить ошибку в отчёт. Даже существующий `_redact_secrets` защищает только форму `Bearer …`, а не любое появление значения ключа.  
   **Предложение:** публичные сообщения формировать по разрешённому списку `provider_code`, без сырого ответа и исключения; добавить тесты с синтетическим ключом на ошибки JSON, envelope и транспорта, проверяя ответ и захваченные логи.

2. **SSE стирает несохранённые правки и сообщение о конфликте.**  
   **Где:** задача 12, П:5392–5396, 5413–5415, 5578, 5607–5618; задача 4, П:2217–2219.  
   Ключ карточки содержит `snap.last_seq`. Любое подходящее событие вызывает загрузку снимка и перемонтирование **всех** карточек с новым `draft` из сервера. Пользователь пишет сцену 2, другая вкладка сохраняет сцену 1 — черновик сцены 2 исчезает. События другого проекта тоже подходят: `project_id` не фильтруется. После 409 аналогично исчезает установленный в карточке alert. Тест конфликта подменяет `onChanged` на `vi.fn()`, поэтому реального перемонтирования не видит.  
   **Предложение:** стабильный ключ по `scene.id`, явное согласование серверной версии с локальным черновиком, сохранение сообщения о конфликте, фильтрация событий проекта. Добавить интеграционный тест страницы с SSE и двумя редактируемыми сценами.

3. **При первой выкладке Docker-файлы не попадут на сервер.**

   **Предложение:** коммит координатора после локального гейта поставить **до** bundle и выкладки. Проверять SHA доставленного коммита.

5. **Мастер S1 не покрывает часть заявленного интерфейса.**

Основные кнопки S1 не закреплены снизу на телефоне, хотя это требование явно перенесено и в ограничения плана.

6. **«Строгая схема» сценариста не обеспечена на всех поддерживаемых маршрутах.**  
   **Где:** задачи 8, 9, 11, П:3259, 3716–3717, 4794–4803; [provider.py:912](</Users/aleksey.korzhebin/Yandex.Disk.localized/Projects/minimax-h3-mlx-48gb/h3_48gb/provider.py:912>), [test_provider.py:1914](</Users/aleksey.korzhebin/Yandex.Disk.localized/Projects/minimax-h3-mlx-48gb/tests/test_provider.py:1914>).  
   Существующий `_chat_turn` проверяет схему локально только для `json_object`; для `json_schema` доверяет серверу. Это прямо закреплено старым тестом. Ответ `{}` проходит клиент, затем `raw["scenes"]` даёт необработанный `KeyError`, то есть 500 вместо предусмотренного `llm_failed`. Аналогично карточка героя.  
   **Предложение:** валидировать ответ на границе студии независимо от режима провайдера; нарушения превращать в безопасный 502. Добавить отсутствующие поля, неверные типы и повторяющиеся `cast_tags`.

7. **Фикстуры изображений закрепляют приём повреждённых файлов.**  
   **Где:** задача 9, П:3432, 3444–3455, 3584–3596; задача 11, П:4583–4585.  
   «PNG» состоит из сигнатуры и нулей — это не декодируемая картинка. `sniff()` принимает её, а тест проверяет только возврат тех же байтов. В браузере получится битое изображение, хотя API и тест зелёные.  
   **Предложение:** использовать настоящие минимальные изображения; проверять декодирование перед импортом. Отдельно тестировать корректную сигнатуру с повреждённым содержимым.

8. **L2 и L6 проверяют более узкие условия, чем написано в спеке.**  
   **Где:** задача 7, П:2928–2935, 2988–2999; R21, П:73; С:849, 853.  
   Воспроизведено:
   - `No music and wind rustles through reeds.` → L2 warning, хотя положительный источник есть;
   - `No music. Nothing is audible.` → нет L2, хотя положительного источника нет;
   - в первой сцене портретная фраза изменена, во второй восстановлена каноническая → L6 молчит в обеих сценах.

   Кроме того, отсутствие героя в следующем кадре трактуется как дрейф его описания: правило не знает состав персонажей сцены.  
   **Предложение:** разделить обнаружение отрицания и положительного звукового источника; для L6 учитывать присутствие персонажа и сравнивать описание по цепочке в обоих направлениях изменения. Добавить эти контрпримеры.

9. **Технические гейты допускают выжившие мутации содержания.**  
   **Где:** задачи 3, 7, 10, 11; П:1235–1253, 2781–2850, 4055–4064, 4600–4621.  
   Конкретные пробелы:
   - **Линтер:** фактически проверено — все 17 запланированных случаев проходят после удаления `words > 500`; также после ограничения L4 одним `music_text` и после замены L12 `>=` на `>`. Нужны границы 39/40/500/501, параметризация EN-полей, равный индекс.
   - **И1:** тест проверяет рост ревизии, но не сохранённое значение каждого изменённого поля. В памяти воспроизвела мутацию SQL, сохраняющую старый `music_text`: ревизия становится 2, музыка остаётся пустой. Нужны точные ожидаемые значения ответа **и повторного чтения**.
   - **И10:** нет конкурентной записи между чтением проекта и `last_seq`; удаление транзакции снимка последовательные тесты не обнаружат. `FakeEventSource` объявлен, но подписка мастера не проверяется.
   - **Сценарист:** `ScriptedLlm` фиксирует только имя схемы; не проверены содержимое схемы, системный промпт и сохранённые `llm_json.raw/prompt_version`. Потеря звука, музыки или портретной фразы второй сцены также не закрыта полным ожидаемым результатом.

   **Предложение:** дополнить гейты этими содержательными проверками и показать красный вывод для соответствующих мутаций.

10. **Мутация `toSceneIn` краснеет на форме, а не на защищаемом поведении.**  
    **Где:** задача 12, П:5129–5144, 5652; сервер П:4256.  
    Фикстура содержит единственную сцену с `kind="none"`. Мутация добавляет `scene_id:null`, и точное сравнение падает. Но это не проверяет пересчёт источника у продолжения: сервер и так использует `source.get("scene_id") or prev_id`. Значимый баг — передача **старого непустого** источника после удаления/перестановки — этим случаем не проверяется.  
    **Предложение:** фикстура из трёх связанных сцен, удаление средней, проверка тела O7 и итогового источника третьей. Мутация должна сохранять прежний непустой ID.

11. **Триггер И2 разрешает запрещённый переход `NULL → NULL`.**  
    **Где:** задача 1, П:264–276, 651–655; С:491.

    **Предложение:** отдельно обеспечить разрешённый переход и добавить отрицательный тест до первой материализации.
