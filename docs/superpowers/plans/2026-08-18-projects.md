## Task 1: хранилище проектов (h3_48gb/project.py)

Create: h3_48gb/project.py, tests/test_project.py.
Produces: create_project(outdir, kind, title) -> Project (kind: video|clip|song); Project.path
(<outdir>/projects/<YYYYMMDD-HHMM>-<слаг>/project.json); load_project / list_projects(outdir);
атомарная запись (tmp+rename) с flock-локом по образцу queue.py; модель: stages со статусами
(draft|awaiting_approval|approved|running|done|failed), scenes: [{idx, prompt, duration, status,
job_id, clip_path, keyframe_path}], track: {lyrics, caption, wav, mp3, mastered_mp3, sections:
[{tag, start, end}], status}, assembly: {audio_mode: song|mix|clips, final_path}.
Методы: approve_stage, set_scene_status, next_pending_scene, invalidate_scene_chain(idx)
(сцена idx и все последующие → pending, их job_id/клипы очищаются — автокейфреймы зависят
от предыдущих). Переживает рестарт (всё в файле). Тесты: круговая запись/чтение, лок,
инвалидация цепочки, list с битым json (пропуск с warning, не падение).

## Task 2: прогон песни (h3_48gb/songrun.py + scripts/music3-generate.py)

Create: scripts/music3-generate.py (версионированная копия ~/models/music3/gen.py — прочитать
и перенести, генерация+тайминги+пик памяти), h3_48gb/songrun.py, tests/test_songrun.py.
Produces: run_song(track_dir, lyrics, caption, duration, *, seed, steps=30, music3_python=...,
model_dir=...) -> SongResult: (1) subprocess music3-venv → wav; (2) мастеринг ffmpeg
(highpass=38, firequalizer как в отработанной цепочке: −2.5 дБ@60, +1.5@3к, +3.5@8к, +4@12к,
loudnorm I=-13.6:TP=-1:LRA=11) → mastered.wav; (3) оба в mp3 (libmp3lame -q:a 1);
(4) Whisper-проверка: subprocess music3-venv (mlx_whisper, large-v3-turbo, language=ru) →
транскрипт; сопоставление с лирикой (нормализация: lowercase, без пунктуации/ё→е; доля
совпавших строк последней трети лирики) → undersung: bool (порог: <60% строк последней
трети найдены) + sections: границы секций по таймстампам сегментов (первый сегмент,
совпавший со строкой секции, задаёт start). Оценка длительности: estimate_duration(lyrics) =
28 с × число секций + 15 с. Все subprocess'ы в тестах мокаются; ffmpeg-цепочка — один
реальный тест на синусе. ВАЖНО: сам Music3 в тестах НЕ запускать (GPU занят).

## Task 3: kind=song и kind=assemble в очереди/воркере

Modify: h3_48gb/queue.py, h3_48gb/worker.py, tests/test_queue.py, tests/test_worker.py.
Задачи очереди получают kind (поле в json задачи, default "generate" для старых — обратная
совместимость обязательна, старые файлы без поля читаются). args-формат: ["song",
"--project", <path>] / ["assemble", "--project", <path>]. Воркер диспатчит по kind:
generate — как сейчас (subprocess h3 generate); song — h3_48gb.songrun.run_song по данным
project.json, по завершении статус трека в project.json → awaiting_approval (гейт!) и job done;
song с track.source=="import" — генерацию и мастеринг пропустить, только Whisper-раскладка
секций импортированного mp3 (align_only-путь songrun) → тот же гейт;
assemble — h3_48gb.assemble.run (Task 4). GPU-лок/лизинг/пауза — без изменений (song жрёт
GPU так же). Оценка song-задачи = estimate_duration × 13 (реалтайм-фактор). Тесты:
диспатч по kind (song/assemble мокаются), обратная совместимость старых задач, гейт-статус.

## Task 4: сборка и цепочка сцен (h3_48gb/assemble.py + продвижение проекта)

Create: h3_48gb/assemble.py, tests/test_assemble.py. Modify: h3_48gb/worker.py (+тесты).
assemble.run(project) -> final_path: ffmpeg concat с перекодировкой в единый профиль
(libx264 crf 18, общий fps), для kind=clip аудио = mastered-трек (-map замена; режим mix —
amix с клипами на −18 дБ), выход <проект>/final.mp4.
Правила из lyric-video-director (проверенные чужой практикой): песня священна — БЕЗ
-shortest (тихо режет хвост аудио), без time-stretch аудио; для kind=clip длительность
final == длительность трека ±0.5 с (валидация в конце run, расхождение = ошибка сборки,
недостающий хвост видео добивается freeze-frame последнего кадра); переходы v1 — только
прямые склейки на границах сцен (границы уже на музыкальных границах секций).
Цепочка сцен: advance_project(project, queue_root, outdir) — вызывается воркером после
каждого done/failed задания проекта: если сцена i done → извлечь автокейфрейм ffmpeg'ом
(кадр из предпоследней секунды клипа, select по времени) → submit сцены i+1 (i2v с этим
кадром, промпт сцены, обычный submit očереди) → обновить project.json; все сцены done →
submit assemble-задачи; сцена failed → проект stage failed (не сыпать дальше). Первая
сцена: t2v (или i2v, если у проекта загружен стартовый кадр). Тесты: продвижение по
статусам с мок-submit, кейфрейм-команда, остановка на failed, идемпотентность (повторный
advance не дублирует submit — по job_id в project.json).

## Task 5: чат — kind:"project" и схема сценария

Modify: h3_48gb/provider.py (PROMPT_SCHEMA), docs/h3-prompt-system.md, h3_48gb/web.py (чат),
tests/test_provider.py, tests/test_web.py.
Схема ответа LLM расширяется необязательным полем project: {kind: video|clip|song,
scenes: [{prompt, duration}], lyrics, caption} (для video — scenes; для clip/song — lyrics+caption,
сцены клипа появятся после трека). Системный промпт дополняется: правила сценария
(N сцен по 5–10 с, связность через visual bible — повторять описания персонажей/стиля в
каждой сцене дословно; формат H3 в каждом prompt), правила лирики Music3 (уроки
«Колыбельной», проверены 5 генерациями: в лирике ТОЛЬКО чистые структурные теги
[intro]/[verse]/[pre-chorus]/[chorus]/[bridge]/[outro] — никаких английских актёрских
директив внутри тегов, они ломают модель (переключение языка, музыка не соответствует
голосу); ВСЯ режиссура — в caption: три секции Global Metadata / Vocal Details /
Arrangement, эмоциональная прогрессия и актёрская задача словами, жанр с эмоциональной
рамкой первым словом; ожидания честные — вокальная актёрка модели ограничена), конвертация
suno-разметки при импорте (STYLE PROMPT-поля → caption, теги с пайпами → чистые теги,
аннотации из пайпов → Arrangement). Чат-сессия хранит kind. Тесты: схема валидирует оба варианта,
system prompt содержит новые разделы.

## Task 6: веб-API проектов

Modify: h3_48gb/web.py, tests/test_web.py (или новый tests/test_web_projects.py).
POST /api/projects (создание из чат-сессии: kind + сцены/лирика из последнего project-поля
сессии, или пустого; для clip-проекта опционально track.source="import" с путём загруженного
mp3 — аплоад существующим /api/uploads — и лирикой); GET /api/projects (список), GET /api/projects/<id> (полный project.json);
POST /api/projects/<id>/approve/<stage> — гейты: сценарий approved → (clip/song) submit
song-задачи ИЛИ (video) старт первой сцены; трек approved → (clip) построить сцены по
секциям трека COVERAGE-COMPLETE (принцип lyric-video-director: таймлайн покрывает 0 →
длительность трека без дыр): спетые секции → сцены из сценария по порядку; инструментальные
интервалы между ними (интро/соло/аутро/паузы) — по длительности: <1.5 с вливается в соседнюю
сцену, ≥1.5 с становится своей сценой с fallback-промптом «инструментальная интерлюдия:
<промпт предыдущей сцены>, no vocals, инструментальная пауза» (без второго LLM-вызова в v1);
секции со start=None (не спеты) пропускаются, их сценарные сцены не используются; сумма
длительностей сцен == длительность трека (валидация при построении). Стартовать первую,
(song) → проект done; POST /api/projects/<id>/scenes/<idx>/retry (инвалидация цепочки
+ resubmit); DELETE /api/projects/<id> (только не-running). /api/state дополняется краткой
сводкой проектов. Пути только внутри outdir (resolve_within). Тесты: полный жизненный цикл
song-проекта и video-проекта с мок-очередью, гейты не перепрыгиваются (403/409), retry
инвалидирует хвост.
