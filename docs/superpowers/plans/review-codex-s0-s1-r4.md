**1. Сохранение после 409 превращает чужое поле в незаметную локальную правку.**  
Место: [П:7812–7823](</Users/aleksey.korzhebin/Yandex.Disk.localized/Projects/minimax-h3-mlx-48gb/docs/superpowers/plans/2026-10-21-studio-s0-s1.md:7812>), формирование следующего PATCH — П:7800–7807.

Воспроизведено извлечёнными `save`, `fromScene`, `sameDraft` и `patchBody`:

1. В другой вкладке сохранён `sound_text = "new remote sound"`, ревизия стала 2.
2. Здесь изменена только музыка. После 409 пользователь нажимает «Сохранить моё»: отправляется `{expected_revision: 2, music_text: "mine-v1"}`.
3. Пока запрос выполняется, пользователь меняет сид на 22.
4. Ответ содержит новый серверный звук и ревизию 3. Код обновляет базу, но сохраняет **весь старый черновик**, включая `"old sound"`.

```json
{
  "expected_revision": 3,
  "sound_text": "old sound",
  "seed": 22
}
```

Он проходит с актуальной ревизией и затирает сохранённый звук без нового конфликта. Пользователь звук не редактировал; при разрешении конфликта это поле также не показывалось среди его изменений.

**Предложение:** переносить изменения после отправки **по полям**: если `current[k] === sent[k]`, принимать `fresh[k]`, иначе сохранять `current[k]`. Добавить задержанный ответ после 409 с изменением другого поля; следующий PATCH должен содержать только новый сид.
