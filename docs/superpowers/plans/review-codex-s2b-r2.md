**Новые блокеры редакции 2**

1. **Готовый ComfyUI допускает тяжёлую задачу, пока LLM поднимается или его `/health` временно недоступен.**

   Новая защита выполняется только при успешном `/health`: [6402](docs/superpowers/plans/2026-10-23-studio-s2b-image.md#L6402). При неуспехе выполнение попадает в прежний ранний возврат `ready`, расположенный **до** проверки GPU-процессов — [текущий диспетчер, 433–445](tools/gpu-dispatcher/dispatcher.py#L433).

   Воспроизводимый путь: тяжёлая партия → `/free` → асинхронный запуск LLM с сохранённым ComfyUI → новая тяжёлая задача до готовности `/health` → `ready` → загрузка Qwen-Image одновременно с поднимающимся LLM. Аналогично готовый движок обходит проверку неопознанных/посторонних GPU-процессов.

   **Нужно:** перед каждым разрешением задачи проверять состояние LLM и GPU, включая ветку готового движка; хранить состояние «LLM запускается». Недоступный health при наличии процессов или незавершённом запуске должен означать ожидание. Нужен тест именно этой последовательности.

2. **Успешный HTTP-ответ `/free` принят за завершённую выгрузку, после чего немедленно запускается LLM.**

   `ComfyExecutor.free()` возвращает `True` сразу после ответа API: [6609](docs/superpowers/plans/2026-10-23-studio-s2b-image.md#L6609); воркер сразу вызывает `qwen_back`: [6658](docs/superpowers/plans/2026-10-23-studio-s2b-image.md#L6658). Ни освобождение VRAM, ни завершение выгрузки не проверяются.

   При этом собственный замер явно разделяет мгновенный ответ API и **трёхсекундную паузу на освобождение памяти**: [отчёт, 226](docs/h3-modes/LLM-PLUS-IMAGE-20261023.md#L226). До выгрузки совместный объём оценён в 92 340 МиБ при доступных 64 912 МиБ: [224](docs/h3-modes/LLM-PLUS-IMAGE-20261023.md#L224).

   **Нужно:** подтверждать освобождение памяти с ограниченным ожиданием; при ошибке или таймауте LLM не запускать. Тест должен моделировать ответ 200 при ещё занятой памяти.

Дополнительно перед исполнением стоит устранить два важных пробела:

- Автоматический `qwen_restore(keep=...)` останавливает **все остальные собственные движки диспетчера без проверки владельца**: [6444](docs/superpowers/plans/2026-10-23-studio-s2b-image.md#L6444). Если между `/free` и восстановлением карта передана панели, её `h3`/`ltx` может быть остановлен. Нужны повторная проверка владельца и отказ/ожидание при чужом активном клиенте.
- Откат противоречив: выкладка меняет диспетчер на [7003](docs/superpowers/plans/2026-10-23-studio-s2b-image.md#L7003), а шаг отката утверждает, что S2b его не меняла: [7016](docs/superpowers/plans/2026-10-23-studio-s2b-image.md#L7016). Следует явно включить восстановление прежнего диспетчера.
