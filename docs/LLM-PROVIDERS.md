# Внешние LLM-провайдеры: что измерено

Замеры живыми вызовами. Всё, что здесь написано, воспроизводилось на настоящем
хосте; догадки помечены прямо. Соседний проект пользователя (`ai-writer 2.0`)
ведёт свой журнал тех же граблей — сверенный отчёт лежит у них в
`docs/reports/2026-08-24-caila-structured-output-cross-project.md`, и часть
выводов ниже пришла оттуда, чтобы не мерить дважды.

## Зачем нам внешняя модель вообще

Сценарий клипа — самая «умная» задача конвейера и самая дешёвая: **один запрос
на клип**, в отличие от генерации видео, которую наружу не отдашь. На боевых
воротах 2026-08-20 локальная модель написала технически безупречный и
драматургически пустой сценарий (претензия пользователя: персонажи перетекают
друг в друга, главная героиня не появляется, атмосферы замысла нет). На том же
входе `claude-opus-5` через caila дал связную драматургию с первого раза.
Отсюда `provider` в теле `POST /api/projects/<id>/scenario/generate`.

## Лимит вывода — главные грабли

**Дефолт caila — 4096 токенов вывода, и он включается при полном отсутствии
ключа лимита.** Рассуждающая модель тратит их на скрытый thinking и возвращает
пустой `content`:

```
finish_reason: length
usage: {'prompt_tokens': 2, 'completion_tokens': 4096, 'total_tokens': 4098}
len(content): 0
```

С явным лимитом та же задача проходит: `max_tokens: 32000` → `finish_reason:
stop`, 19 899 токенов вывода, 43 КБ валидного JSON, 226 секунд.

**Ключ зависит от семейства модели, и слать оба разом нельзя.** Anthropic-роуты
caila молча игнорируют `max_completion_tokens` — им нужен `max_tokens`;
рассуждающие модели OpenAI (`o1`-`o4`, `gpt-5*`) наоборот отвергают
`max_tokens`. Проверено соседним проектом пятью живыми вызовами с бюджетами
4096/32000/200000/1000 (их ADR-126): при `max_completion_tokens=1000` потолок
всё равно 4096, то есть параметр просто не читается.

**Практическая цифра:** одна тяжёлая структурная задача (19 секций сценария с
вложенными объектами и длинными текстами) стоит ~20 тысяч токенов вывода.

## `usage.prompt_tokens` с этого хоста недостоверен

В обоих замерах выше `prompt_tokens: 2` при запросе на 35 892 байта (порядка
девяти тысяч токенов). Для учёта стоимости и оценки заполнения контекста
непригоден. `completion_tokens` выглядит достоверным (ровно 4096 на потолке,
19 899 при успехе). Не проверено, врёт ли он одинаково на всех семействах.

## Строгая схема работает — и это наше преимущество

Мы отправляем `response_format: {"type": "json_schema", "json_schema": SCHEMA}`
со `strict` каждым вызовом (`provider._chat_turn`), и на caila это работает
даже на вложенной схеме сценария (объект → массив секций → вложенный объект
сцены), **с первой попытки, без repair-библиотек**.

Соседний проект просит JSON «мягко» (`{"type": "json_object"}`), а их путь со
строгой схемой спроектирован, но в провод не подключён — то есть здесь мы
впереди, и копировать их вариант не надо. Функциональные вызовы как альтернативу
они рассматривали и отвергли: локальные endpoint'ы поддерживают их неодинаково.

## Маршрут `anthropic-claude` исчез (08.10.2026), Sonnet 5.5 — только через `json_object`

CAILA убрала маршрут `just-ai/anthropic-claude/...`. Sonnet 5.5 доступен только как
`just-ai/openrouter-proxy/anthropic/claude-sonnet-5.5`, и на нём строгая схема
(`response_format: json_schema`) отвечает 400 «tool_choice: type "tool" and "any" are not
supported for this model». С `{"type":"json_object"}` тот же маршрут отвечает 200 примерно за 26 с
чистым JSON.

Поле записи провайдера `"response_format": "json_object"` (по умолчанию `"json_schema"`, как
раньше) включает этот режим: в тело уходит `{"type":"json_object"}`, схема дописывается текстом в
системное сообщение («Ответ — один JSON-объект по этой JSON-схеме: …»), а ответ после разбора
(снятие ```-ограды, `null` для опущенных nullable, удаление лишних ключей) проверяется маленьким
валидатором по той же схеме: обязательные поля, типы, `enum`, `minimum`/`maximum`. Нарушение —
`bad_model_json` и один обычный повтор. На пути `json_schema` поведение не менялось и ответ не
перепроверяется — там схему держит провайдер.

```json
"caila-sonnet": {
  "type": "openai",
  "base_url": "https://caila.io/api/adapters/openai",
  "model": "just-ai/openrouter-proxy/anthropic/claude-sonnet-5.5",
  "api_key_env": "CAILA_API_KEY",
  "response_format": "json_object",
  "max_tokens_param": "max_tokens",
  "max_tokens": 32000,
  "stream": false,
  "shares_gpu": false,
  "send_temperature": false
}
```

Код, не знающий поля, его молча игнорирует и шлёт `json_schema` — то есть получит тот же 400;
запись менять только вместе с выкладкой этого кода.

## Stream: не для скорости, а против таймаута шлюза

Долго не использовали вовсе, и по правильным причинам: пайплайн фоновый,
результат нужен целиком, промежуточные токены некуда показывать. Соседний
проект пришёл к тому же выводу с другой стороны — они stream выключали,
столкнувшись с тем, что thinking-модели льют рассуждение в чанки и рвут
per-chunk таймауты (их ADR-065). Замера «быстрее ли» в цифрах нет ни у одной
стороны, и он не нужен: быстрее не становится.

**Но 2026-08-24 нашёлся довод, которого у соседей не было.** Шлюз caila
обрывает долгий запрос: генерация сценария полной песни на `claude-opus-5`
упала через 7 мин 16 с с `RemoteDisconnected: Remote end closed connection
without response`, тогда как более короткий запрос к той же модели прошёл за
226 с. То есть потолок не в модели, а в шлюзе, и лежит он между четырьмя и
семью минутами. Поток держит соединение чанками — это и есть обход, и ровно
его ADR-065 называет единственным настоящим доводом за stream. Соседям он не
понадобился (у них короткие шаги), нам понадобился: у нас одна тяжёлая
структурная задача на весь клип, ~20 тысяч токенов вывода.

Включается на провайдера полем `stream` в `providers.json`, по умолчанию
выключен — не-потоковый путь остаётся штатным для локального llama-server и
всех, кому обход не нужен. Рассуждение из дельт (`reasoning`,
`reasoning_content`, `thinking`) в ответ не попадает: собирается только
`content`. Обрезка распознаётся в потоке тем же кодом, что и в обычном
режиме — `finish_reason` из последнего чанка идёт через общий контракт, так
что отдельной «потоковой» ветки для неё не существует и рассинхронизироваться
нечему.

## Диагностируемость: не выдавать обрезку за нарушение схемы

Первый живой запуск упал с сообщением «модель не удержала формат» — потому что
пустой `content` не проходил разбор и падал в ту же ветку, что настоящее
нарушение схемы. Сообщение было ложью: модель формат не нарушала, ей не дали
договорить. Диагностика заняла час и потребовала ручных вызовов мимо продукта.

Признаки обрезки, которые надо проверять ДО попытки разбора: `finish_reason ==
"length"`, пустой `content` при ненулевом `usage.completion_tokens`, незакрытый
JSON. Обрезка и нарушение схемы — разные отказы, с разными сообщениями и
разными действиями; повтор с тем же лимитом бессмыслен.

## `temperature`

Мы шлём её всегда. На `claude-opus-5` через caila 2026-08-24 принимается
(HTTP 200). У соседнего проекта записан инцидент, когда caila депрекейтнула
`temperature` у claude и уронила им слой проверки — то есть поведение хоста
менялось, и постоянным запрет считать нельзя. Рассуждающие модели OpenAI
`temperature` отвергают.

## Как завести провайдера

`providers.json` в `H3_OUTDIR`, секреты — только именем переменной:

```json
"caila-opus5": {
  "type": "openai",
  "base_url": "https://caila.io/api/adapters/openai",
  "model": "just-ai/anthropic-claude/claude-opus-5",
  "api_key_env": "CAILA_API_KEY"
}
```

Сам ключ — в `.env` рядом, права `600`. **`base_url` пишется БЕЗ `/v1`**: код
дописывает `/v1/chat/completions` и `/v1/models` сам, а некоторые провайдеры
(OpenRouter) в своей документации дают адрес уже с `/v1` — скопировав его
дословно, получишь `/v1/v1/...` и 404 везде, включая чат.

Проверить, не тратя GPU и времени: `POST /api/providers/<name>/test` — дешёвый
`GET {base_url}/v1/models` для внешнего, `port_alive` для локального.
